# 컴퓨터 성능의 이해와 측정

## 1. 성능의 이해와 정의

### Slide 3: 성능 (Performances)
컴퓨터 구조에서 가장 핵심적인 개념 중 하나인 '성능'에 대해 다루는 단원의 시작입니다. 이 파트에서는 컴퓨터의 성능을 어떻게 정의하고 측정할 것인지에 대한 이론적 배경을 학습합니다.

### Slide 4: 성능에 영향을 미치는 요소
컴퓨터의 성능은 단순히 CPU의 속도로만 결정되지 않고 여러 계층의 요소가 복합적으로 작용합니다.
* **알고리즘**: 실행할 연산의 전체적인 횟수를 결정합니다.
* **프로그래밍 언어, 컴파일러, 아키텍처**: 각 연산을 처리하기 위해 실행되어야 하는 기계어 명령어의 수를 결정합니다.
* **프로세서와 메모리 시스템**: 명령어가 얼마나 빠르게 실행되는지를 결정합니다.
* **I/O 시스템 (운영체제 포함)**: 입출력 작업이 얼마나 빠르게 실행되는지를 결정합니다.

### Slide 5: 성능의 정의
비행기의 예시를 통해 성능을 정의하는 기준이 다양할 수 있음을 보여줍니다. 여객기의 성능을 평가할 때 승객 수용력, 순항 범위, 순항 속도, 승객 처리량 등 어떤 지표를 기준으로 삼느냐에 따라 가장 성능이 뛰어난 비행기가 달라집니다. 컴퓨터 역시 사용 목적에 따라 성능을 평가하는 척도가 달라져야 함을 의미합니다.

### Slide 6: 응답 시간과 처리량
컴퓨터 성능을 평가하는 두 가지 주요 지표입니다.
* **응답 시간(Response Time)**: 실행 시간(Execution time)이라고도 하며, 디스크 및 메모리 접근, I/O 작업, OS 오버헤드 등을 모두 포함하여 하나의 작업을 완료하는 데 걸리는 총 시간입니다. 주로 초 단위로 측정됩니다.
* **처리량(Throughput)**: 단위 시간당 완료된 작업의 총량을 의미합니다. 컴퓨터가 여러 프로그램을 동시에 처리하는 환경에서는 개별 프로그램의 응답 시간을 줄이는 것보다 전체 시스템의 처리량을 최적화하는 것이 중요할 수 있습니다.

### Slide 7: 성능 향상의 변수
프로세서를 더 빠른 버전으로 교체하거나, 프로세서의 개수를 늘리는(멀티코어/다중 프로세서) 방식이 응답 시간과 처리량에 각각 어떤 영향을 미치는지 고민해 보는 단계입니다. 본 강의에서는 우선 단일 작업의 '응답 시간'을 기준으로 성능을 분석하는 데 초점을 맞춥니다.

## 2. 성능 측정과 공식

### Slide 8: 상대적 성능
성능은 실행 시간의 역수로 정의할 수 있습니다.
$Performance=\frac{1}{Execution~time}$
컴퓨터 X가 컴퓨터 Y보다 빠르다는 것은 X의 성능이 Y보다 높다는 뜻이며($Performance_{X}>Performance_{Y}$), 이는 곧 X의 실행 시간이 Y보다 짧다는 의미입니다. "X가 Y보다 n배 빠르다"는 다음 공식으로 표현됩니다.
$\frac{Performance_{X}}{Performance_{Y}}=\frac{Execution~time_{Y}}{Execution~time_{X}}=n$

### Slide 9: 상대적 성능 계산 예시
동일한 프로그램을 실행할 때 컴퓨터 A는 10초가 걸리고 컴퓨터 B는 15초가 걸렸다면, A가 B보다 얼마나 빠른지 계산할 수 있습니다.
$\frac{Execution~time_{B}}{Execution~time_{A}}=\frac{15s}{10s}=1.5$
결과적으로 컴퓨터 A는 컴퓨터 B보다 1.5배 빠릅니다.

### Slide 10: 성능 측정 지표
시간은 컴퓨터 성능을 측정하는 가장 기본적이고 확실한 척도입니다.
* **경과 시간(Elapsed time)**: 처리, I/O, OS 오버헤드, 유휴 시간 등을 모두 포함한 전체 응답 시간으로, 시스템의 전체 성능을 나타냅니다.
* **CPU 시간(CPU time)**: 특정 작업을 처리하기 위해 순수하게 CPU가 소비한 시간입니다. I/O 시간이나 다른 작업이 대기하는 시간은 제외됩니다.
또한 명령어 처리에 걸리는 평균 클럭 사이클 수를 의미하는 **CPI(Clock cycles per instruction)** 역시 하드웨어 성능을 평가하는 중요한 지표로 사용됩니다.

### Slide 11: CPU 클럭

디지털 하드웨어의 동작은 일정한 주기를 갖는 클럭(Clock)에 의해 제어됩니다. 클럭 신호는 전압이 높고 낮은 상태를 일정한 주파수로 진동하며, 메트로놈처럼 디지털 회로의 동작을 동기화합니다. 이 클럭 신호에 맞추어 데이터 전송, 연산, 상태 업데이트가 동시에 일어납니다.

### Slide 12: 클럭 주기와 주파수
* **클럭 주기(Clock period)**: 한 번의 클럭 사이클이 지속되는 시간입니다. (예: $250ps=0.25ns=250\times10^{-12}s$)
* **클럭 주파수(Clock rate)**: 초당 발생하는 클럭 사이클의 수입니다. (예: $4.0GHz=4000MHz=4.0\times10^{9}Hz$)
클럭 주파수와 클럭 주기는 서로 역수 관계에 있습니다.

### Slide 13: CPU 시간 도출
성능을 향상시키려면 클럭 사이클 수를 줄이거나 클럭 속도를 높여야 합니다. 그러나 하드웨어 설계자는 이 두 요소 사이에서 트레이드오프(상충 관계)를 고려해야 합니다. CPU 실행 시간은 다음과 같이 도출됩니다.
$\text{CPU Time} = \text{CPU Clock Cycles} \times \text{Clock Cycle Time}$
이를 주파수로 변환하면 다음과 같습니다.
$\text{CPU Time} = \frac{CPU~Clock~Cycles}{Clock~Rate}$

### Slide 14: CPU 시간 예제
컴퓨터 A는 2GHz 클럭으로 10초의 CPU 시간을 가집니다. 컴퓨터 B를 설계할 때 목표 CPU 시간을 6초로 잡고 더 빠른 클럭을 적용하려고 하지만, 그 대가로 컴퓨터 A보다 1.2배 많은 클럭 사이클이 필요해졌습니다. 이때 B의 목표 클럭 속도를 계산하면 다음과 같습니다.
A의 전체 클럭 사이클 수: $10s\times2GHz=20\times10^{9}$
B의 전체 클럭 사이클 수: $1.2\times20\times10^{9}=24\times10^{9}$
B의 필요 클럭 속도: $\frac{24\times10^{9}}{6s}=4GHz$

### Slide 15: 명령어 개수와 CPI
프로그램 실행에 필요한 전체 클럭 사이클 수는 명령어 개수(Instruction Count)와 명령어당 평균 클럭 사이클(CPI)의 곱으로 표현할 수 있습니다. 이를 바탕으로 CPU 시간을 계산하는 최종 공식이 완성됩니다.
$\text{CPU Time} = \frac{Instruction~Count\times CPI}{Clock~Rate}$

### Slide 16: CPI 활용 예제
컴퓨터 A(사이클 타임 $250ps$, CPI 2.0)와 컴퓨터 B(사이클 타임 $500ps$, CPI 1.2)에서 동일한 ISA 기반 프로그램을 실행할 때의 성능을 비교합니다.
A의 CPU 시간: $I\times2.0\times250ps=I\times500ps$
B의 CPU 시간: $I\times1.2\times500ps=I\times600ps$
$\frac{CPU~time_{B}}{CPU~time_{A}}=1.2$가 되므로 컴퓨터 A가 1.2배 더 빠릅니다.

### Slide 17: 상세한 CPI 도출
모든 명령어가 동일한 사이클을 소모하지는 않습니다. 명령어 클래스별로 소모하는 사이클이 다를 경우, 전체 클럭 사이클은 각 클래스의 (CPI $\times$ 명령어 수)를 모두 합하여 계산합니다. 이를 통해 가중 평균이 적용된 전체 평균 CPI를 도출하는 공식은 다음과 같습니다.
$CPI=\sum_{i=1}^{n}(CPI_{i}\times\frac{Instruction~Count_{i}}{Instruction~Count})$

### Slide 18: 상세 CPI 계산 예제
명령어 클래스 A, B, C가 각각 1, 2, 3의 CPI를 가질 때, 두 가지 코드 시퀀스의 성능을 비교합니다.
* **시퀀스 1**: 명령어 5개 사용. 총 사이클 수 $2\times1+1\times2+2\times3=10$. 평균 CPI는 $\frac{10}{5}=2.0$
* **시퀀스 2**: 명령어 6개 사용. 총 사이클 수 $4\times1+1\times2+1\times3=9$. 평균 CPI는 $\frac{9}{6}=1.5$
명령어 개수는 시퀀스 1이 더 적지만, 클럭 사이클 수와 평균 CPI를 고려하면 시퀀스 2가 더 효율적일 수 있음을 보여줍니다.

### Slide 19: 성능 요약
최종적으로 컴퓨터의 CPU 실행 시간을 결정하는 세 가지 주요 요소는 다음과 같습니다.
$CPU~Time=\frac{Instructions}{Program}\times\frac{Clock~cycles}{Instruction}\times\frac{Seconds}{Clock~cycle}$
알고리즘, 프로그래밍 언어, 컴파일러, ISA는 각기 다른 방식으로 명령어 수, CPI, 그리고 사이클 타임에 영향을 미치게 됩니다.

## 3. CPU와 구성 요소

### Slide 20: CPU와 그 구성 요소
성능 측정 파트를 마치고, 본격적으로 컴퓨터 구조의 핵심인 CPU 내부로 진입하는 전환점입니다.

### Slide 21: CPU, 메모리, 입출력(I/O)
CPU(처리 장치)와 메모리(저장 장치) 사이의 상호작용을 나타냅니다. CPU는 메모리로 주소(Address)를 보내고, 데이터(Data)와 명령어(Instruction)를 양방향으로 주고받으며 연산 및 제어 작업을 수행합니다.

### Slide 22: 마이크로컴퓨터의 기본 요소

시스템 버스(System bus)를 중심으로 CPU, 메모리(ROM, RAM), 칩셋, 입출력장치가 어떻게 연결되어 있는지 보여주는 전체적인 블록 다이어그램입니다. 이 버스 시스템을 통해 하드웨어 요소 간에 데이터를 주고받게 됩니다.

### Slide 23: 버스 (Bus)
버스는 정보를 교환하기 위해 CPU와 하드웨어 요소들을 연결해 주는 물리적인 신호선들의 집합입니다. 하드웨어적으로 설치된 전선의 다발이며, 0 또는 1로 구성된 2진 데이터가 이 통로를 통해 전송됩니다.

### Slide 24: 버스의 종류
버스는 역할에 따라 크게 세 가지로 나뉩니다.
* **주소 버스(Address bus)**: CPU가 외부 기억장치의 위치를 지정하기 위해 내보내는 단방향 신호선입니다. 배선의 수가 최대 메모리 용량을 결정합니다(예: 16비트면 $2^{16}$개 주소 지정).
* **데이터 버스(Data bus)**: CPU와 장치 간에 데이터를 주고받는 양방향 통로입니다. 버스의 폭(width)이 한 번에 전송할 수 있는 비트 수를 결정합니다.
* **제어 버스(Control bus)**: 메모리나 I/O 장치에 읽기/쓰기 등의 동작을 지시하는 제어 신호를 전달합니다.

## 버스와 컴퓨터 시스템 아키텍처 (Slides 25-37)

### Slide 25: Bus의 종류 - Cont'd
이전 슬라이드에 이어 버스의 종류와 데이터 흐름을 시각적으로 보여줍니다. CPU, 메모리(Memory), 입출력 장치(I/O device)가 주소 버스(Address bus), 16가닥의 선으로 이루어진 데이터 버스(Data bus), 그리고 제어 버스(Control bus)를 통해 서로 연결되어 통신하는 구조를 확인할 수 있습니다.

### Slide 26: Bus의 동작 원리
CPU와 RAM 간의 읽기 및 쓰기 동작이 시간 흐름에 따라 어떻게 이루어지는지 타이밍 다이어그램으로 설명합니다.
* **쓰기 동작**: 주소 버스에 기록할 주소가 먼저 실리고, 이어서 데이터 버스에 기록할 데이터가 실린 후, 마지막으로 쓰기 신호가 활성화됩니다.
* **읽기 동작**: 주소 버스에 읽어올 주소가 실린 후 읽기 신호가 활성화되면, 메모리에서 해당 주소의 데이터를 찾아 데이터 버스에 실어 보냅니다.

### Slide 27: Computer 구조

서버 등 상위 기종을 포함한 마이크로컴퓨터의 전반적인 구조도입니다. 중앙처리장치(CPU)와 메모리는 빠른 속도를 위해 메모리 컨트롤러를 거쳐 시스템 버스(System bus)로 연결됩니다. 반면 마우스, 키보드, 하드디스크 등 상대적으로 속도가 느린 입출력 장치들은 I/O 컨트롤러를 거쳐 I/O 버스로 연결되는 계층적 구조를 가집니다.

### Slide 28: Address와 controller
컴퓨터 하드웨어는 메모리와 I/O 장치를 제어하는 방식과 주소 체계를 구분합니다.
* **주소 체계**: 메모리 주소(주로 RAM)와 I/O 주소(HDD 등 보조기억장치 및 기타 장치)로 나뉩니다.
* **컨트롤러**: CPU를 보조하여 하드웨어를 직접 제어하는 칩셋입니다. 메모리 장치를 제어하는 Memory controller와 입출력 장치를 제어하는 I/O controller로 구분됩니다.

### Slide 29: System bus와 I/O bus
버스 시스템을 속도와 목적에 따라 두 가지로 명확히 구분합니다.
* **System bus**: CPU, 메인 메모리, 주요 칩셋을 연결하는 고속 통로입니다. 제어 시간을 절약하기 위해 RAM 모듈을 CPU의 동작 주기에 동기화시킵니다.
* **I/O bus**: I/O 컨트롤러와 다양한 입출력 장치를 연결합니다. 장치마다 필요한 비트 수와 속도가 다르므로 여러 종류의 버스 규격이 혼용되어 사용됩니다.

### Slide 30: I/O bus 처리과정
키보드와 프린터를 예시로 CPU와 I/O 장치 간의 통신 방식을 설명합니다. CPU는 주소 버스와 데이터 버스를 통해 각 장치의 제어기(Controller) 내부에 있는 '상태 레지스터'와 '데이터 레지스터'에 접근하여 I/O 읽기 및 쓰기 동작을 수행합니다.

### Slide 31: I/O bus 처리과정: 키보드 예
사용자가 키보드를 누를 때 데이터가 입력되는 과정을 순서도로 나타냅니다. 키가 눌리면 해당 ASCII 코드가 데이터 레지스터에 저장되고, 상태 레지스터의 $In\_RDY$ 비트가 1로 세트됩니다. CPU는 상태 레지스터를 반복적으로 읽어 $In\_RDY=1$인지 검사하고, 1이 확인되면 그때 데이터 레지스터에서 값을 읽어옵니다.

### Slide 32: Chipset
칩셋(Chipset)은 여러 제어 칩과 회로가 모여 시스템 전체를 제어하도록 설계된 조합입니다. 컴퓨터 메인보드 상에 위치하여 프로세서와 함께 하드웨어를 제어하며, 특정 CPU 아키텍처와 호환되도록 맞춤 설계됩니다. 내부에는 버스 제어기, 메모리 제어기, 인터럽트 제어기, 타이머 등이 포함됩니다.

### Slide 33: Chipset의 구성
전통적인 칩셋은 성능과 속도에 따라 두 부분으로 나뉩니다.
* **North bridge (MCH)**: 메모리 컨트롤러 등 고속 장치와의 통신을 담당합니다.
* **South bridge (ICH)**: I/O 컨트롤러 등 저속 입출력 장치와의 통신을 담당합니다.

### Slide 34: Chipset은 CPU 프로세서에 대한 플랫폼
전통적인 노스브리지/사우스브리지 구조의 한계와 해결책을 보여줍니다. 기존 방식은 모든 데이터가 노스브리지를 거치는 전면 버스(FSB, Front-Side Bus) 구조여서 병목현상이 발생했습니다. 이를 해결하기 위해 점진적으로 노스브리지의 기능을 CPU 칩 내부로 통합하는 방식이 도입되었습니다.

### Slide 35: Chipset의 구성 추세
칩셋의 발전 동향을 설명합니다. 초기에는 비디오 어댑터 인터페이스를 노스브리지에 통합했고, 이후 메모리 접근 병목현상을 해결하기 위해 노스브리지 전체를 프로세서 칩 내부에 통합했습니다. 현재는 사우스브리지의 일부 기능까지 흡수한 PCH(Platform Controller Hub) 형태로 진화했으며, 점차 모든 칩셋 기능을 프로세서 칩 하나에 내장하는 SoC(System on Chip) 형태로 발전하고 있습니다.

### Slide 36: 인텔 4세대 Core 프로세서 플랫폼 (2013.09)
노스브리지 기능이 CPU 내부로 통합된 과도기적 구조를 보여줍니다. 시스템 메모리와 디스플레이 인터페이스가 CPU에 직접 연결되어 독립적인 고속 채널을 형성하며, 사우스브리지 역할을 하는 PCH가 분리되어 존재합니다.

### Slide 37: 인텔 5세대 Core 프로세서 플랫폼 (2015.01)
칩셋의 통합이 더욱 진행된 형태입니다. CPU와 같은 반도체 기판 위에 칩셋(PCH 포함)이 함께 내장되어, 하나의 패키지 안에서 센서 허브, 네트워크, 저장장치 컨트롤러 등 대부분의 시스템 제어 기능이 통합 처리됩니다.

## CPU 구성 요소와 레지스터 (Slides 38-44)

### Slide 38: Central processing unit (CPU)
CPU의 기본적인 역할과 용어를 정의합니다. CPU는 프로그램의 명령어를 인출 및 해독하고, 데이터를 연산하여 결과를 저장하거나 전송합니다. 여기서 진행 중인 작업은 Process, 처리하는 과정 자체는 Processing, 그리고 그 주체인 하드웨어 모듈이나 칩을 Processor라고 부릅니다.

### Slide 39: Central processing unit (CPU) 구성요소

CPU 내부를 구성하는 3대 핵심 요소를 소개합니다.
* **ALU (Arithmetic and Logic Unit)**: 산술 연산과 논리 연산을 직접 수행하는 연산 장치입니다.
* **Register**: 연산에 필요한 명령, 주소, 데이터를 일시적으로 저장하는 CPU 내부의 초고속 기억장소입니다.
* **Control unit (제어장치)**: 명령어를 해석하고, 메모리 및 I/O 장치에 읽기/쓰기 신호 등 시스템 전체를 통제하는 제어 신호를 발생시킵니다.

### Slide 40: Central processing unit (CPU) 구성요소 (Diagram)
CPU 내부의 요소들이 어떻게 통신하는지 다이어그램으로 보여줍니다. CPU 외부의 메모리 및 I/O와 연결되는 외부 데이터 버스(System bus)가 CPU 내부의 I/O unit을 거쳐 내부 데이터 버스(Internal data bus)로 연결되며, 이를 통해 ALU, Control unit, Registers가 데이터를 교환합니다.

### Slide 41: Register
레지스터에 대해 본격적으로 다루는 섹션의 시작을 알리는 타이틀 슬라이드입니다.

### Slide 42: Register의 구성
CPU 내부에 존재하는 다양한 레지스터들의 연결 구조를 보여주는 다이어그램입니다. PC, MAR, MBR, IR, AC 등의 특정 목적을 가진 레지스터와 연산 데이터를 임시로 보관하는 기타 범용 레지스터들이 내부 버스를 통해 ALU 및 제어장치와 연결되어 있습니다.

### Slide 43: Register의 구성 - 상세 역할
다이어그램에 등장한 주요 레지스터들의 가상적인 명칭과 역할을 명확히 정의합니다.
* **AC (Accumulator)**: 연산에 가장 빈번하게 사용되며, 연산 결과를 다시 자신에게 누적 저장합니다.
* **PC (Program counter)**: 다음에 실행할 명령어의 메모리 주소를 가리킵니다.
* **MAR (Memory address register)**: 메모리에 접근하기 전 주소 버스로 나갈 주소를 임시 저장합니다.
* **MBR (Memory buffer register)**: 데이터 버스를 통해 메모리와 주고받을 데이터를 임시 저장합니다.
* **IR (Instruction register)**: 메모리에서 방금 인출된 명령어를 저장하여 해독할 수 있게 합니다.

### Slide 44: Register의 구성 - RISC-V 예시
현대적인 아키텍처인 RISC-V에서 실제로 사용되는 레지스터들의 목록을 표로 제시합니다. 범용 레지스터인 $x0$부터 $x31$까지의 이름과 용도(예: 상수 0을 반환하는 zero, 스택 포인터 sp, 임시 변수용 temporaries 등)를 보여주며, 부동소수점 연산을 위한 $f0$부터 $f31$까지의 레지스터도 별도로 존재함을 명시합니다. 프로시저 호출 시 값을 보존하는 주체(Caller/Callee)에 대한 규약도 포함되어 있습니다.

# 3. 명령어 집합 구조(ISA) 및 분류 (Slides 45-69)

## ISA의 정의와 하드웨어-소프트웨어 인터페이스 (Slides 45-50)

### Slide 45: 산술 논리 연산 장치 (ALU)
CPU 내부의 핵심 연산 장치인 ALU(Arithmetic and Logic operation Unit)에 대해 다루는 섹션의 시작을 알리는 슬라이드입니다.

### Slide 46: ALU의 구성
ALU는 수치 데이터에 대한 산술 연산과 2진 데이터에 대한 논리 연산을 실제 수행하는 하드웨어입니다. 주요 구성 요소로는 연산 결과의 상태를 저장하는 상태 레지스터(Status register), 음수 연산을 위한 2의 보수기(2's complementer), $+,-,\times,\div$를 수행하는 산술 연산기, NOT, AND, OR 등을 수행하는 논리 연산기, 그리고 비트 열을 이동시키는 시프트 레지스터가 있습니다.

### Slide 47: ALU의 연산 동작

8비트 데이터 버스를 통해 데이터가 이동하고 연산되는 과정을 보여주는 블록 구조입니다. 예를 들어 $AC \leftarrow AC+B$ 연산을 수행할 때, 누산기(AC)와 범용 레지스터(B)의 값이 임시 레지스터(TEMP1, TEMP2)로 이동한 뒤 ALU로 입력됩니다. ALU에서 연산된 결과는 다시 AC로 저장되며, 연산 상태는 상태 레지스터(flag)에 기록됩니다.

### Slide 48: 명령어 집합 구조 (ISA): CISC vs. RISC
명령어 집합 구조(Instruction Set Architecture, ISA)의 개념과 대표적인 두 가지 설계 방식인 CISC와 RISC를 비교하는 새로운 주제의 시작 슬라이드입니다.

### Slide 49: 프로그램의 실행 과정
우리가 작성한 응용 프로그램이 실제 하드웨어에서 어떻게 구동되는지 계층적으로 보여줍니다. C언어와 같은 프로그래밍 언어로 작성된 코드는 컴파일러, 운영체제 등 소프트웨어 계층을 거쳐, 궁극적으로 하드웨어 설명 언어, 디지털 논리 회로, 트랜지스터 등 물리적인 하드웨어 계층에서 처리됩니다.

### Slide 50: 명령어 집합 구조 (ISA)
ISA는 소프트웨어와 하드웨어가 소통하기 위한 인터페이스이자 규약입니다. 운영체제나 컴파일러 제작자 등 소프트웨어 개발자가 볼 수 있는 하드웨어의 추상화된 모습으로, 지원하는 명령어의 종류, 데이터 타입, 레지스터, 메모리 주소 지정 방식 등을 명세한 문서와 같습니다. 동일한 ISA를 공유한다면 내부 마이크로아키텍처가 달라도 같은 소프트웨어를 실행할 수 있습니다.

## 설계 철학의 비교: CISC vs. RISC (Slides 51-60)

### Slide 51: RISC-V 레지스터
현대적인 RISC 아키텍처인 RISC-V의 레지스터 구성을 보여줍니다. 32개의 범용 레지스터와 32개의 부동소수점 레지스터로 구성되며, 각 레지스터는 $x0$부터 $x31$, $f0$부터 $f31$까지 고유의 이름과 반환 주소, 스택 포인터 등의 명확한 용도를 가지고 있습니다.

### Slide 52: ISA의 세부 특성
ISA를 구성하는 세부적인 특성들을 RISC-V를 기준으로 설명합니다. 바이트 단위의 메모리 주소 지정, 레지스터 및 변위 기반의 주소 지정 방식, 8비트부터 64비트까지의 피연산자 크기, 그리고 데이터 전송, 산술, 제어 흐름 등을 제어하는 명령어의 형태와 고정 길이 인코딩 방식을 채택하고 있음을 보여줍니다.

### Slide 53: RISC-V 명령어 예시 1
교재(Computer Architecture)에 수록된 RISC-V 명령어 집합의 일부입니다. 메모리와 레지스터 간에 데이터를 이동시키는 데이터 전송 명령어(Load/Store)와 산술/논리 연산을 수행하는 명령어(Add, Sub, Mul, And 등)들의 의미를 구체적으로 나열하고 있습니다.

### Slide 54: RISC-V 명령어 예시 2
앞선 슬라이드에 이어, 프로그램의 실행 흐름을 제어하는 조건부 분기 및 점프 명령어(beq, bne, jal 등)와 부동소수점 연산을 위한 명령어(fadd, fsub 등)의 종류와 의미를 설명합니다.

### Slide 55: CISC의 개념
CISC(Complex Instruction Set Computers)는 가능한 한 적은 줄의 어셈블리 코드로 작업을 완료하는 것을 목표로 설계된 아키텍처입니다. 복잡한 명령어를 하드웨어가 직접 처리하도록 하여, $MULT~2:3,5:2$ 처럼 한 번의 명령으로 메모리 간의 곱셈을 수행할 수 있습니다. 코드 크기가 작아 메모리 사용량이 적다는 장점이 있습니다.

### Slide 56: RISC의 개념
RISC(Reduced Instruction Set Computers)는 하나의 클럭 사이클 내에 실행될 수 있는 단순한 명령어들로만 구성하는 아키텍처입니다. CISC의 곱셈 명령어 하나를 처리하기 위해 RISC는 데이터를 레지스터로 불러오고(LOAD), 연산하고(PROD), 다시 저장하는(STORE) 여러 단계의 단순 명령어로 나누어 처리합니다. 명령어 길이를 균일하게 하여 파이프라이닝(Pipelining)을 적용하기 용이합니다.

### Slide 57: CISC와 RISC의 특징 비교
두 아키텍처의 장단점을 대조합니다. CISC는 하드웨어에 복잡성을 전가하여 코드 크기를 줄이는 반면, RISC는 소프트웨어(컴파일러)에 복잡성을 전가하고 단순한 명령어를 통해 초당 실행 사이클 속도를 높이는 데 집중합니다. 특히 RISC는 메모리 접근 명령(LOAD/STORE)을 독립시켜 레지스터 활용도를 극대화합니다.

### Slide 58: CISC와 RISC의 발전 동향
Intel의 x86 프로세서는 CISC를 대표하며 높은 유연성을 갖지만 전력 소모가 큽니다. 반면 ARM이나 Apple M1 프로세서는 RISC 기반으로 저전력에 특화되어 있습니다. 다만, 현대에 이르러 Intel은 내부적으로 RISC 방식을 혼용하고, ARM은 성능 향상을 위해 복잡한 명령어를 추가하면서 두 아키텍처 간의 경계는 점차 모호해지고 있습니다.

### Slide 59: RISC-V
2010년 UC 버클리에서 개발된 현대적인 오픈소스 RISC 명령어 집합입니다. 과거 아키텍처들의 장점은 취하고 단점은 배제하여 설계되었으며, 구글, 마이크로소프트, 삼성 등 글로벌 기업들이 참여하는 재단을 통해 유지보수되고 있는 유망한 아키텍처입니다.

### Slide 60: 컴퓨터 아키텍처의 정의
과거의 컴퓨터 아키텍처가 단순히 명령어 집합(ISA)을 설계하는 것에 국한되었다면, 현대의 '실질적인' 컴퓨터 아키텍처는 비용, 전력, 가용성 등의 제약 조건 속에서 성능을 극대화하기 위해 ISA는 물론 마이크로아키텍처와 하드웨어 설계 전반을 아우르는 개념으로 확장되었음을 설명합니다.

## 피연산자 위치에 따른 ISA 분류 (Slides 61-66)

### Slide 61: 추상화의 전체 계층

소프트웨어부터 하드웨어까지의 전체 계층도를 다시 한번 강조합니다. 이 중 'Architecture(ISA)'가 소프트웨어와 하드웨어를 나누는 정확한 경계선이자 인터페이스로 작용하고 있음을 붉은색 상자로 명확히 표시하고 있습니다.

### Slide 62: 명령어 집합 구조의 분류
본격적으로 ISA를 어떻게 분류할 것인지 다루는 소단원의 제목 슬라이드입니다.

### Slide 63: 내부 저장소 위치에 따른 분류
ISA는 프로세서 내부에서 피연산자(Operand)를 어디에 보관하는지에 따라 크게 세 가지로 분류됩니다.
* **Stack**: 연산 시 최상단(TOS) 데이터를 암시적으로 사용합니다.
* **Accumulator**: 하나의 누산기(AC)를 암시적으로 사용합니다.
* **General-purpose register (GPR)**: 범용 레지스터를 사용하며, 레지스터와 메모리 간의 접근 방식에 따라 레지스터-메모리 구조와 로드-스토어 구조로 다시 나뉩니다.

### Slide 64: 연산 아키텍처별 동작 예시
$C=A+B$라는 동일한 연산을 네 가지 구조에서 어떻게 처리하는지 보여줍니다.
* **Stack**: A와 B를 차례로 Push하고 Add한 뒤 C로 Pop합니다.
* **Accumulator**: A를 Load하고 B를 Add한 뒤 C로 Store합니다.
* **Register-memory**: 레지스터와 메모리 값을 직접 연산할 수 있습니다.
* **Load-store**: A와 B를 각각 레지스터로 Load한 뒤 연산하고, 그 결과를 다시 메모리로 Store합니다.

### Slide 65: 현대 컴퓨터가 Load-Store 구조를 채택하는 이유
현대의 컴퓨터 아키텍처가 Load-store(Register-register) 구조를 선호하는 이유는 레지스터가 메인 메모리보다 훨씬 빠르기 때문입니다. 변수를 레지스터에 보관하면 메모리 트래픽이 줄어들고 프로그램 속도가 크게 향상되며, 메모리 주소보다 레지스터 번호를 가리키는 데 적은 비트가 소모되어 코드 밀도도 개선됩니다.

### Slide 66: GPR 아키텍처의 특성
범용 레지스터(GPR) 구조는 ALU 명령어의 피연산자 개수(2개 또는 3개)와 메모리 주소를 피연산자로 사용할 수 있는 개수(0개~3개)에 따라 세분화됩니다. ARM, MIPS, RISC-V 등은 연산 명령어에 메모리 주소를 포함할 수 없는(0개) 전형적인 Load-store 구조에 속합니다.

## 메모리 접근 방식: Load-Store 구조의 이해 (Slides 67-69)

### Slide 67: 아키텍처별 장단점 비교
* **Register-register (Load-store)**: 명령어 길이가 고정되어 있고 파이프라이닝이 단순하지만, 메모리 접근 명령이 별도로 필요해 전체 명령어 수는 많아집니다.
* **Register-memory**: 명령어가 간결해지지만, 한쪽 피연산자가 연산 후 덮어씌워져 파괴될 수 있고 클럭 사이클이 가변적입니다.
* **Memory-memory**: 레지스터 낭비가 없고 코드가 가장 짧지만, 메모리 병목현상이 극심하여 현재는 사용되지 않습니다.

### Slide 68: Memory (Load-store) 다이어그램
Load-store 구조 프로세서의 동작 원리를 요약하는 구조도입니다. 용량이 작고 속도가 빠른 프로세서 내부의 레지스터(Registers)와, 용량이 크고 속도가 느린 외부의 메모리(Memory) 공간이 철저히 분리되어 있습니다. 데이터 연산(ALU)은 오직 레지스터 간에만 이루어지며, 메모리와의 소통은 오직 Load(메모리 읽기)와 Store(메모리 쓰기) 명령을 통해서만 일어나는 구조를 직관적으로 보여줍니다.
