# 1. 컴퓨터 성능의 이해와 측정 (Slides 3-24)

## 성능의 정의와 영향 요소 (Slides 3-5)

### Slide 3: 성능 (Performances)
컴퓨터 구조와 설계에 있어서 성능(`Performance`)의 기초를 다루는 단원입니다. 교재 'Computer Organization and Design RISC-V Edition'의 1.6절에 해당하는 내용으로, 컴퓨터 하드웨어와 소프트웨어 인터페이스에서 성능을 어떻게 정의하고 접근할 것인지에 대한 개요를 제시합니다.

### Slide 4: 성능의 이해 (Understanding Performance)
컴퓨터의 성능은 단일 하드웨어 부품만으로 결정되지 않으며, 여러 요소가 복합적으로 작용하여 결정됩니다. 각 요소가 성능에 미치는 영향은 다음과 같이 세분화할 수 있습니다.
* `알고리즘`: 실행해야 할 전체 연산의 횟수를 결정합니다.
* `프로그래밍 언어, 컴파일러, 아키텍처`: 하나의 연산을 처리하기 위해 실행되어야 하는 기계어 명령어의 수를 결정합니다.
* `프로세서와 메모리 시스템`: 각 명령어가 얼마나 빠르게 실행되는지를 결정합니다.
* `입출력(I/O) 시스템 및 운영체제`: 입출력 작업이 완료되는 데 걸리는 속도를 결정합니다.
이러한 각 계층의 요소들을 종합적으로 이해해야 시스템의 전체 성능을 정확히 파악할 수 있습니다.

### Slide 5: 성능의 정의 (Defining performance)
성능이라는 개념은 평가 기준에 따라 달라질 수 있습니다. 슬라이드에서는 4종류의 비행기(Airbus A380-800, Boeing 777-200LR, Concorde, Boeing 737)를 예시로 들어 이를 설명합니다. 
* 승객 수용력(`Passenger capacity`)을 기준으로 하면 Airbus A380-800이 가장 우수합니다.
* 순항 거리(`Cruising range`)를 기준으로 하면 Boeing 777-200LR이 가장 우수합니다.
* 순항 속도(`Cruising speed`)를 기준으로 하면 Concorde가 가장 우수합니다.
* 승객 처리량(`Passenger throughput`, 승객 수 $\times$ 속도)을 기준으로 하면 다시 Airbus A380-800이 가장 우수합니다.
이처럼 컴퓨터 시스템에서도 사용자의 목적과 기준에 따라 "가장 성능이 좋은 컴퓨터"에 대한 정의가 달라질 수 있음을 객관적인 지표 비교를 통해 시사합니다.

## 응답 시간(Response Time)과 처리량(Throughput) (Slides 6-7)

### Slide 6: 응답 시간과 처리량 (Response Time and Throughput)
컴퓨터 성능을 평가하는 두 가지 주요 지표는 응답 시간과 처리량입니다. 성능 측정을 위해서는 어떤 지표가 중요한지 명확한 정의가 필요합니다.
* `응답 시간(Response Time)`: 실행 시간(`Execution time`), 실제 시간(`Wall clock time`), 경과 시간(`Elapsed time`)이라고도 합니다. 디스크 및 메모리 접근, 입출력 작업, 운영체제 오버헤드 등을 모두 포함하여 하나의 작업을 완료하는 데 걸리는 총 시간을 의미합니다. 보통 초 단위로 측정됩니다.
* `처리량(Throughput)`: 단위 시간당 완료된 총 작업량을 의미합니다. (예: 시간당 처리하는 트랜잭션 수)
일반적으로 다수의 사용자가 공유하거나 여러 프로그램을 동시에 실행하는 컴퓨터 시스템의 경우, 개별 프로그램의 응답 시간을 최소화하는 것보다 전체적인 시스템 처리량을 최적화하는 데 집중하는 경우가 많습니다.

### Slide 7: 응답 시간과 처리량의 변화 요소 (Response Time and Throughput - cont'd)
시스템의 구성 요소를 변경했을 때 응답 시간과 처리량이 어떻게 영향을 받는지 분석합니다.
* 프로세서를 더 빠른 버전으로 교체하는 경우: 단일 작업의 처리 속도가 빨라지므로 응답 시간이 감소하고, 단위 시간당 처리할 수 있는 작업도 많아져 처리량 역시 증가합니다.
* 프로세서를 추가하는 경우: 한 번에 여러 작업을 병렬로 처리할 수 있으므로 전체 처리량은 크게 증가합니다. 하지만 단일 작업 자체의 응답 시간은 프로세서 추가만으로 직접적인 개선이 이루어지지 않을 수 있습니다.
이후 강의에서는 성능의 기준을 우선 '응답 시간(실행 시간)'에 초점을 맞추어 논의를 진행합니다.

## 상대적 성능과 실행 시간의 관계 (Slides 8-9)

### Slide 8: 상대적 성능 (Relative Performance)
성능(`Performance`)은 실행 시간(`Execution time`)의 역수로 정의할 수 있습니다. 이를 수식으로 나타내면 $Performance=\frac{1}{Execution~time}$이 됩니다.
만약 컴퓨터 X의 성능이 컴퓨터 Y보다 뛰어나다면, 이를 $Performance_{X}>Performance_{Y}$로 표기할 수 있으며, 이는 즉 $\frac{1}{Execution~time_{X}}>\frac{1}{Execution~time_{Y}}$임을 의미합니다. 결과적으로 컴퓨터 X의 실행 시간이 Y의 실행 시간보다 짧다는 것을 수학적으로 증명할 수 있습니다.
"컴퓨터 X가 Y보다 $n$배 빠르다"는 개념은 다음 공식을 통해 상대적 성능 비율로 계산합니다.
$\frac{Performance_{X}}{Performance_{Y}}=\frac{Execution~time_{Y}}{Execution~time_{X}}=n$

### Slide 9: 상대적 성능 계산 예시 (Relative Performance - Cont'd)
상대적 성능 공식에 실제 값을 대입하여 계산하는 과정을 보여주는 예시입니다.
동일한 프로그램을 실행할 때 컴퓨터 A에서는 10초가 소요되었고, 컴퓨터 B에서는 15초가 소요되었다고 가정합니다. 앞서 정의한 공식을 적용하면 다음과 같습니다.
$\frac{Execution~time_{B}}{Execution~time_{A}}=\frac{15s}{10s}=1.5$
계산 결과 값이 1.5가 도출되며, 이는 컴퓨터 A의 성능이 컴퓨터 B보다 1.5배 빠르다는 것을 객관적으로 수치화한 결과입니다.

# CPU 클럭 지표와 명령어 성능 지표

## CPU 클럭 지표: Clock Rate 및 Clock Cycle (Slides 10-14)

### Slide 10: 성능 측정 지표의 이해 (Measuring performance)
컴퓨터의 성능을 제대로 평가하기 위해서는 '시간'을 정확히 측정해야 합니다. 여기서는 시간을 측정하는 두 가지 관점을 소개합니다. 첫째는 `경과 시간(Elapsed time)`으로, 데이터 입출력(I/O) 대기 시간이나 운영체제 작업 등을 모두 포함하여 사용자가 느끼는 전체 응답 시간을 뜻합니다. 둘째는 `CPU 시간(CPU time)`으로, 순수하게 해당 작업을 처리하기 위해 CPU가 실제로 연산에 사용한 시간만을 의미합니다. 하드웨어 성능을 깊이 분석할 때는 I/O 대기 시간 등의 외부 요인을 제외한 CPU 시간을 주로 살펴봅니다. 추가로, 명령어 하나를 처리하는 데 필요한 평균 클럭 사이클인 `CPI(Clock cycles per instruction)`라는 중요한 개념도 등장합니다.


### Slide 11: CPU 클럭 (CPU Clock)

컴퓨터는 수많은 미세한 부품들이 모여 있는 복잡한 기계입니다. 이 부품들이 서로 엉키지 않고 정확한 순서에 맞춰 일하게 하려면 모두가 맞추어야 할 '공통된 박자'가 필요한데, 그것이 바로 **클럭(Clock)**입니다.

* **메트로놈과 같은 역할**: 음악가들이 메트로놈 박자에 맞춰 연주하듯, 디지털 하드웨어 내부의 모든 사건(데이터 이동, 계산 등)은 이 클럭 신호에 맞춰 발생합니다.
* **클럭 신호의 형태**: 슬라이드의 그림을 보면 일정한 간격으로 위아래로 진동하는 사각형 모양의 그래프(Square Wave)를 볼 수 있습니다. 
    * 신호가 낮은 곳에서 높은 곳으로 올라가는 순간을 **상승 엣지(Rising edge)**라고 합니다.
    * 보통 이 '박자'가 딱 떨어지는 순간에 맞춰 CPU 내부의 스위치들이 작동하며 데이터를 처리합니다.

### 왜 클럭이 중요한가요?
1.  **동기화(Synchronization)**: 부품 A가 보낸 데이터를 부품 B가 정확한 타이밍에 받도록 약속해 줍니다.
2.  **성능의 척도**: 이 박자가 빠르면 빠를수록(즉, 1초에 더 많은 박자를 칠수록) CPU는 같은 시간 동안 더 많은 일을 처리할 수 있게 됩니다. 우리가 CPU 사양을 볼 때 흔히 말하는 '$3.5GHz$' 같은 숫자가 바로 이 박자의 속도를 의미합니다.

### Slide 12: 클럭 주기와 주파수 (CPU Clocking - Cont'd)
클럭 신호를 수치화하는 두 가지 핵심 개념입니다.
* `클럭 주기(Clock period)`: 한 번의 클럭 사이클이 완료되는 데 걸리는 '시간'입니다. 예를 들어 $250ps$는 매우 짧은 찰나의 시간입니다.
* `클럭 주파수(Clock frequency/rate)`: 1초 동안 클럭 사이클이 몇 번 반복되는지를 나타내는 '횟수'입니다. 예를 들어 $4.0GHz$는 1초에 40억 번의 클럭이 발생한다는 뜻입니다.
이 둘은 서로 역수 관계에 있으므로, 주파수가 높아질수록 주기는 짧아집니다.

### Slide 13: CPU 시간 공식의 도출 (CPU Time)
성능을 높이려면 프로그램 실행에 필요한 전체 클럭 사이클 수를 줄이거나, 클럭 주파수를 높여 박자를 빠르게 만들어야 합니다. 하드웨어 설계자는 이 사이에서 최적의 균형을 찾아야 합니다. CPU 실행 시간을 도출하는 공식은 다음과 같습니다.
$CPU~execution~time=\frac{CPU~Clock~Cycles}{Clock~Rate}$
이 공식은 "총 필요한 박자 수"를 "1초에 치는 박자 수"로 나눈 것으로, 순수하게 연산에 걸린 시간을 초 단위로 계산해 줍니다.

### Slide 14: CPU 시간 계산 예제 (CPU time example)
앞서 배운 공식을 실제 설계 문제에 적용해 보는 예제입니다.
컴퓨터 A는 $2GHz$의 클럭으로 10초의 CPU 시간이 걸립니다. 이를 통해 A의 전체 클럭 사이클 수가 $20\times10^9$번임을 알 수 있습니다.
새로운 컴퓨터 B를 설계할 때 목표 CPU 시간을 6초로 단축하려 합니다. 하지만 구조 변경으로 인해 필요한 클럭 사이클 수가 A보다 1.2배 늘어났습니다($24\times10^9$번). 목표 시간인 6초 안에 이 늘어난 사이클을 모두 처리하려면, 컴퓨터 B의 클럭 주파수는 $4GHz$가 되어야 함을 공식($Clock~Rate_B=\frac{24\times10^9}{6s}$)을 통해 도출할 수 있습니다.

## 명령어 성능 지표: CPI 및 CPU Time 공식 (Slides 15-24)

### Slide 15: 명령어 개수와 CPI의 관계 (Instruction Count and CPI)
전체 클럭 사이클 수는 프로그램에 포함된 총 `명령어 개수(Instruction count)`와 명령어 한 개당 필요한 평균 사이클 수인 `CPI`를 곱하여 구할 수 있습니다. 이를 바탕으로 컴퓨터 구조에서 가장 중요한 최종 성능 공식이 완성됩니다.
$CPU~Time=\frac{Instruction~Count\times CPI}{Clock~Rate}$
즉, CPU 시간은 명령어 개수가 적을수록, CPI가 낮을수록, 클럭 주파수가 높을수록 단축됩니다.

### Slide 16: CPI를 활용한 성능 비교 예제 (CPI Example)
같은 명령어 집합 구조(ISA)를 사용하는 두 컴퓨터 A와 B의 성능을 공식으로 비교합니다.
컴퓨터 A는 클럭 주기가 $250ps$이고 CPI가 2.0입니다. 반면 컴퓨터 B는 클럭 주기가 $500ps$로 더 느리지만, 구조가 효율적이어서 CPI가 1.2로 낮습니다.
수식에 대입해 보면 A의 실행 시간은 $I\times500ps$, B의 실행 시간은 $I\times600ps$가 됩니다. 즉, 클럭 속도가 두 배 빠른 컴퓨터 A가 B보다 최종적으로 1.2배 더 좋은 성능을 냅니다.

### Slide 17: 상세한 CPI 도출 (CPI in More Detail)
지금까지는 모든 명령어의 CPI가 같다고 가정했지만, 실제 프로세서에서는 덧셈, 나눗셈, 메모리 읽기 등 명령어의 종류(클래스)에 따라 필요한 클럭 사이클이 각기 다릅니다. 따라서 전체 프로그램의 정확한 평균 CPI를 구하려면, 각 명령어 클래스의 CPI에 해당 명령어가 전체에서 차지하는 비율을 곱하여 모두 더해주는 '가중 평균' 방식을 사용해야 합니다.
$CPI=\sum_{i=1}^{n}(CPI_i\times\frac{Instruction~Count_i}{Instruction~Count})$

### Slide 18: 가중 평균 CPI 계산 예제 (CPI Example)
가중 평균 CPI를 구하는 실제 예시입니다. 클래스 A, B, C의 CPI가 각각 1, 2, 3이라고 할 때 컴파일된 두 가지 코드 시퀀스를 비교합니다.
* 시퀀스 1: 명령어 5개 사용. 총 사이클 수 10. 평균 $CPI=2.0$
* 시퀀스 2: 명령어 6개 사용. 총 사이클 수 9. 평균 $CPI=1.5$
시퀀스 1이 명령어 개수는 더 적지만 무거운 명령어를 많이 사용하여 전체 사이클이 늘어났습니다. 반면 시퀀스 2는 명령어 개수는 많아도 가벼운 명령어를 위주로 구성되어 총 실행 시간이 더 짧아졌습니다. 컴파일러의 최적화가 성능에 미치는 영향을 잘 보여줍니다.

### Slide 19: 컴퓨터 성능 결정 요소 요약 (Performance Summary)
지금까지 다룬 성능 결정 요소들을 총정리합니다.
$CPU~Time=\frac{Instructions}{Program}\times\frac{Clock~cycles}{Instruction}\times\frac{Seconds}{Clock~cycle}$
이 세 가지 항목에 각 기술이 어떻게 영향을 미치는지 이해해야 합니다. 알고리즘과 프로그래밍 언어는 주로 '명령어 개수'에 영향을 주며, 컴파일러와 ISA(명령어 집합 구조)는 '명령어 개수'뿐만 아니라 'CPI'와 '클럭 주기' 모두에 복합적인 영향을 미칩니다.

### Slide 20: CPU와 그 구성 요소 (CPU and its components)
성능 측정과 공식에 대한 학습을 마치고, 이제 하드웨어의 실질적인 구조인 CPU 내부를 파헤쳐 보는 새로운 섹션으로 넘어가는 표지 슬라이드입니다.

### Slide 21: CPU, 메모리, 입출력 구조 (CPU, memory and I/O)

컴퓨터 시스템의 가장 기본적인 뼈대입니다. 처리 장치인 CPU와 데이터 보관소인 Memory(메모리) 사이의 상호작용을 보여줍니다. CPU는 메모리 쪽으로 찾고자 하는 `주소(Address)`를 보내고, 그 주소에 해당하는 `데이터(Data)`와 `명령어(Instruction)`를 양방향으로 주고받으며 연산을 수행합니다.

### Slide 22: 마이크로컴퓨터의 기본 구성 요소 (CPU, memory and I/O - Cont'd)
CPU, 메모리, 칩셋, 그리고 입출력장치(키보드, 모니터 등)가 어떻게 연결되어 있는지 보여주는 전체 블록 다이어그램입니다. 이 모든 장치들은 각각 따로 노는 것이 아니라 `시스템 버스(System bus)`라는 공용 도로망을 통해 유기적으로 연결되어 데이터를 교환합니다.

### Slide 23: 버스(Bus)의 개념 (Bus)
앞선 슬라이드에서 등장한 '버스'에 대한 명확한 정의입니다. 컴퓨터 구조에서 버스란 승객을 실어 나르는 자동차가 아니라, 전자 부품들 사이에서 0과 1로 이루어진 2진 데이터를 실어 나르는 '신호선(전선)들의 다발'을 의미합니다. 하드웨어들이 서로 정보를 교환하는 통로 역할을 합니다.

### Slide 24: 버스의 세 가지 종류 (Bus의 종류)
버스는 그 역할에 따라 크게 세 가지로 분류됩니다.
* `주소 버스(Address bus)`: CPU가 메모리나 입출력 장치의 특정 위치를 콕 집어 가리킬 때 사용하는 단방향 통로입니다. 이 선의 개수가 컴퓨터가 인식할 수 있는 최대 메모리 용량을 결정합니다.
* `데이터 버스(Data bus)`: 실제로 데이터가 오고 가는 양방향 통로입니다. 이 버스의 폭(비트 수)이 한 번에 처리할 수 있는 데이터의 양을 결정합니다.
* `제어 버스(Control bus)`: CPU가 다른 장치들에게 "이제 읽어라", "이제 써라" 하고 지시를 내리는 제어 신호가 지나가는 통로입니다.

# 2. CPU 구조와 주요 구성 요소 (Slides 25-44)

## CPU의 기본 구조: 제어 장치와 데이터패스 (Slides 25-29)

### Slide 25: Bus의 종류 - Cont'd
컴퓨터 내부의 3대 핵심 요소인 CPU, 메모리(Memory), 입출력 장치(I/O device)가 버스를 통해 어떻게 물리적으로 연결되어 있는지 상세히 보여줍니다. 
* 주소 버스(Address bus)는 CPU에서 메모리나 I/O 장치 방향으로만 나가는 단방향 통로입니다. 
* 데이터 버스(Data bus)는 실제 데이터가 오고 가는 양방향 통로로, 예시에서는 16가닥의 선(16 wires)으로 구성되어 한 번에 16비트를 전송할 수 있음을 나타냅니다.
* 제어 버스(Control bus)는 읽기 및 쓰기 등 장치의 동작을 지시하는 신호를 전달합니다.

### Slide 26: Bus의 동작 원리

CPU와 RAM 간의 읽기(Read) 및 쓰기(Write) 동작이 시간 흐름에 따라 어떻게 이루어지는지 타이밍 다이어그램으로 설명합니다.
* **쓰기 동작**: CPU가 주소 버스에 기록할 위치(주소)를 먼저 싣고, 이어서 데이터 버스에 기록할 데이터를 싣습니다. 마지막으로 쓰기 신호를 활성화하여 메모리에 데이터를 저장합니다.
* **읽기 동작**: CPU가 주소 버스에 읽어올 위치(주소)를 싣고 읽기 신호를 활성화합니다. 그러면 메모리가 해당 주소의 데이터를 찾아 데이터 버스에 실어 CPU로 보냅니다.

### Slide 27: Computer 구조

서버나 고성능 PC 등 상위 기종을 포함한 마이크로컴퓨터의 전반적인 계층 구조입니다. 
빠른 속도가 생명인 CPU와 메모리는 '메모리 컨트롤러'를 거쳐 고속의 시스템 버스(System bus)로 연결됩니다. 반면 마우스, 키보드, 하드디스크처럼 상대적으로 속도가 느린 입출력 장치들은 'I/O 컨트롤러'를 거쳐 I/O 버스로 연결됩니다. 이러한 계층 분리를 통해 전체 시스템의 병목 현상을 줄이고 데이터 전송 효율을 높입니다.

### Slide 28: Address와 controller
컴퓨터 하드웨어는 제어 대상에 따라 주소 체계와 컨트롤러를 명확히 구분하여 관리합니다.
* **주소 체계**: 주로 반도체 램(RAM)을 가리키는 메모리 주소와, 하드디스크(HDD) 등 보조기억장치를 포함한 나머지 장치들을 가리키는 I/O 주소로 나뉩니다.
* **컨트롤러(Controller)**: CPU를 도와 하드웨어를 제어하는 칩셋입니다. 메모리를 전담하는 Memory controller와 입출력 장치를 전담하는 I/O controller로 역할이 분리되어 있습니다.

### Slide 29: System bus와 I/O bus
버스 시스템은 연결하는 장치의 속도와 목적에 따라 두 가지로 명확히 구분됩니다.
* **System bus**: CPU, 메인 메모리, 주요 칩셋을 연결하는 고속 통로입니다. 제어 시간을 절약하기 위해 RAM 모듈의 동작을 CPU에 동기화시킵니다.
* **I/O bus**: I/O 컨트롤러와 다양한 입출력 장치 사이를 연결합니다. 키보드, 모니터, 네트워크 카드 등 장치마다 필요한 데이터 비트 수와 전송 속도가 다르기 때문에, 여러 종류의 규격화된 I/O 버스가 사용됩니다.

## 레지스터(Registers): 유형 및 역할 (Slides 30-38)
*(참고: 이 단락의 슬라이드들은 입출력 제어와 칩셋의 발전 과정을 통해 CPU 외부 레지스터와의 통신 및 플랫폼 진화 과정을 설명합니다.)*

### Slide 30: I/O bus 처리과정
CPU가 I/O 버스를 통해 외부 입출력 장치와 데이터를 주고받는 기본 원리를 설명합니다. 키보드 제어기나 프린터 제어기 내부에는 장치의 현재 상태를 나타내는 '상태 레지스터'와 실제 데이터를 임시 보관하는 '데이터 레지스터'가 존재합니다. CPU는 주소 버스, 데이터 버스, 그리고 I/O 읽기/쓰기 신호를 이용해 이 레지스터들에 접근함으로써 외부 장치를 제어합니다.

### Slide 31: I/O bus 처리과정: 키보드 예
사용자가 키보드를 누를 때 데이터가 CPU로 전달되는 과정을 순서도로 나타냅니다. 
키가 눌리면 해당 문자의 ASCII 코드가 제어기의 데이터 레지스터에 저장되고, 동시에 상태 레지스터의 $In\_RDY$ 비트가 1로 세트됩니다. CPU는 상태 레지스터를 반복적으로 읽어 $In\_RDY=1$이 되었는지 검사하고, 1이 확인되었을 때 비로소 데이터 레지스터에서 값을 읽어옵니다.

### Slide 32: Chipset


[Image of computer motherboard chipset]

칩셋(Chipset)은 여러 제어 칩과 회로가 모여 시스템 전체를 제어하도록 설계된 조합(Set)입니다. 컴퓨터 메인보드에 장착되어 CPU를 보조하며, 특정 CPU 모델에 맞춰 하드웨어를 구성하도록 설계됩니다. 칩셋 내부에는 버스 컨트롤러, 메모리 컨트롤러, I/O 컨트롤러, 인터럽트 컨트롤러 등 다양한 필수 제어 장치들이 포함되어 있습니다.

### Slide 33: Chipset의 구성
전통적인 컴퓨터 칩셋은 성능과 역할에 따라 두 개의 주요 칩으로 나뉘었습니다. '브리지'나 '허브'라는 명칭은 이들이 데이터 통신의 중심 연결 장치임을 의미합니다.
* **North bridge (MCH)**: 메모리 컨트롤러를 포함하며, CPU, RAM, 그래픽 카드 등 고속으로 동작하는 장치들을 제어합니다.
* **South bridge (ICH)**: I/O 컨트롤러를 포함하며, 디스크 드라이브, USB, 오디오 등 상대적으로 저속으로 동작하는 주변 장치들을 제어합니다.

### Slide 34: Chipset은 CPU 프로세서에 대한 플랫폼

전통적인 칩셋 구조가 가진 한계와 그 해결책을 설명합니다. 과거에는 모든 데이터가 노스브리지와 연결된 전면 버스(FSB, Front-Side Bus)로 집중되어 심각한 병목현상이 발생했습니다. 이 문제를 해결하기 위해 고속 데이터 통신이 필요한 노스브리지의 핵심 기능들을 점진적으로 CPU 프로세서 칩 내부로 내장(통합)하는 아키텍처 혁신이 이루어졌습니다.

### Slide 35: Chipset의 구성 추세
컴퓨터 아키텍처가 발전하면서 칩셋의 통합화가 가속화된 과정을 요약합니다. 
초기에는 비디오 어댑터 인터페이스를 노스브리지에 내장했고, 이후 멀티코어 프로세서의 메모리 접근 속도를 높이기 위해 노스브리지 자체를 프로세서 칩 내부에 통합했습니다. 결과적으로 전통적인 사우스브리지 기능과 남은 일부 제어 기능은 PCH(Platform Controller Hub)로 통합되었으며, 궁극적으로는 모든 칩셋 기능을 프로세서 칩 하나에 집어넣는 방향으로 발전하고 있습니다.

### Slide 36: 인텔 4세대 Core 프로세서 플랫폼 (2013.09)
노스브리지가 CPU 내부로 완전히 통합된 2013년도 아키텍처의 블록 다이어그램입니다. 
프로세서(CPU) 칩 내부에 메모리 컨트롤러가 내장되어 시스템 메모리와 독립적이고 직접적인 고속 채널을 형성하고 있습니다. 하단에는 과거 사우스브리지의 역할을 담당하는 PCH(Platform Controller Hub)가 분리되어 존재하며, 디스플레이, USB, 오디오 등의 I/O 장치들을 제어합니다.

### Slide 37: 인텔 5세대 Core 프로세서 플랫폼 (2015.01)

칩셋 통합이 한 단계 더 진화한 2015년도 아키텍처입니다. 
프로세서와 PCH 칩셋이 각각 별도의 칩으로 존재하던 4세대와 달리, CPU와 칩셋이 하나의 동일한 반도체 기판 위에 내장된 모습을 보여줍니다. 이를 통해 공간을 절약하고 전력 효율을 극대화하며, 터치스크린, 자이로 센서 등 모바일 환경에 필요한 다양한 센서와 네트워크 기능까지 단일 플랫폼에서 제어할 수 있게 되었습니다.

### Slide 38: Central processing unit (CPU)
시스템 버스와 칩셋에 대한 설명을 마치고, 컴퓨터의 진정한 두뇌인 CPU의 역할을 다시 한번 정의하는 슬라이드입니다. CPU는 프로그램에서 명령어를 인출(Fetch)하고 해독(Decode)하며, 이에 따라 데이터를 연산하고 그 결과를 저장하거나 전송하는 역할을 수행합니다.
* **Process**: 연산이나 처리를 위해 현재 실행 중인 작업이나 프로그램을 뜻합니다.
* **Processing**: 작업의 처리 및 그 과정 자체를 의미합니다.
* **Processor**: 컴퓨터 내부에 포함된 연산 모듈, CPU 칩 자체를 지칭하는 하드웨어적 용어입니다.

# 2. CPU 구조와 주요 구성 요소 (Slides 39-44)

## 산술 논리 장치(ALU) 및 레지스터의 구성

### Slide 39: Central processing unit (CPU) 구성요소
이 슬라이드에서는 CPU 내부를 구성하는 세 가지 핵심 하드웨어 요소를 정의합니다.
* **연산장치(ALU, Arithmetic and Logic operation Unit)**: 덧셈, 뺄셈 같은 산술 연산과 AND, OR 같은 논리 연산을 실제 수행하는 부분입니다.
* **레지스터(Register)**: 연산을 수행하기 위해 명령어, 주소, 데이터 등을 일시적으로 저장하는 CPU 내부의 아주 빠른 임시 기억장소입니다.
* **제어장치(Control unit)**: 메모리에서 가져온 명령어를 해석하고, 이를 실행하기 위해 시스템 전체에 필요한 제어 신호(읽기, 쓰기, 타이밍 신호 등)를 발생시킵니다.

### Slide 40: Central processing unit (CPU) 구성요소 (다이어그램)

CPU의 내부 구성 요소들이 어떻게 데이터를 주고받는지 시각화한 구조도입니다. 외부 메모리 및 입출력 장치와 연결되는 외부 데이터 버스(시스템 버스)가 I/O 유닛을 거쳐 CPU 내부로 들어옵니다. CPU 내부에는 고유의 '내부 데이터 버스(Internal data bus)'가 존재하며, 이 내부 통로를 통해 ALU, 제어장치, 레지스터들이 유기적으로 데이터를 교환하며 연산을 수행하게 됩니다.

### Slide 41: Register 단원 도입
CPU의 핵심 구성 요소 중 하나인 '레지스터(Register)'에 대해 본격적으로 깊이 있게 다루기 시작하는 표지 슬라이드입니다.

### Slide 42: Register의 구성
다양한 종류의 레지스터들이 CPU 내부에서 어떻게 배치되어 있고, 외부 버스와 어떻게 연결되는지 보여주는 블록 다이어그램입니다.
프로그램 카운터(PC), 메모리 주소 레지스터(MAR), 메모리 버퍼 레지스터(MBR), 명령어 레지스터(IR), 누산기(AC) 등 특수 목적을 가진 레지스터들과 기타 범용 레지스터들이 내부 버스를 통해 ALU 및 제어장치와 통신합니다. 또한 MAR은 주소 버스로, MBR은 데이터 버스로 직접 연결되어 외부 메모리와 소통하는 창구 역할을 합니다.

### Slide 43: Register의 구성 및 상세 역할
앞선 다이어그램에 등장한 필수 가상 레지스터들의 구체적인 역할을 하나씩 정의합니다.
* **AC (Accumulator, 누산기)**: 연산에 가장 빈번하게 사용되며, 연산의 대상이 되는 데이터를 일시 저장하고 연산 결과가 다시 자신에게 누적되어 저장되는 레지스터입니다.
* **PC (Program counter)**: 다음에 실행할 명령어의 메모리 주소를 기억하고 있습니다.
* **MAR (Memory address register)**: CPU가 외부로 주소를 출력하기 직전에 해당 주소를 잠시 보관하는 레지스터입니다.
* **MBR (Memory buffer register)**: 데이터 버스를 통해 외부 메모리에서 읽어오거나 외부로 쓸 데이터를 임시로 저장합니다.
* **IR (Instruction register)**: 메모리에서 가장 최근에 가져온(인출된) 명령어를 보관하여 제어장치가 이를 해독할 수 있게 합니다.
* **기타 범용 레지스터**: 연산 도중 포인터(데이터 주소 저장)나 카운터(데이터 개수 저장) 등 다양한 일시적 기억장소로 유연하게 활용됩니다.

### Slide 44: Register의 구성 (RISC-V 실제 사례)
가상적인 레지스터 개념을 넘어, 실제 현대 아키텍처인 RISC-V에서는 레지스터가 어떻게 구성되어 있는지 표를 통해 보여줍니다.
RISC-V는 32개의 범용 레지스터($x0$~$x31$)와 32개의 부동소수점 레지스터($f0$~$f31$)를 제공합니다. 각 레지스터는 항상 0 값을 가지는 $x0(zero)$, 함수 복귀 주소를 저장하는 $x1(ra)$, 스택 구조를 관리하는 $x2(sp)$ 등 명확한 이름과 용도가 지정되어 있습니다. 또한, 함수를 호출할 때 해당 레지스터의 값을 누가 보존해야 하는지(Caller 또는 Callee)에 대한 소프트웨어적 규약까지 함께 정의되어 있어 하드웨어와 소프트웨어 간의 긴밀한 인터페이스를 보여줍니다.

# 3. 명령어 집합 구조(ISA) 및 분류 (Slides 45-69)

## ISA의 정의와 하드웨어-소프트웨어 인터페이스 (Slides 45-50)

### Slide 45: 산술 논리 연산 장치 (ALU)
CPU 내부에서 실제 연산을 담당하는 산술 논리 연산 장치(ALU)에 대해 다루는 부분의 시작입니다.

### Slide 46: ALU의 구성
ALU는 수치 데이터에 대한 산술 연산과 2진 데이터에 대한 논리 연산을 수행합니다. 주요 구성 요소로는 연산 결과의 상태를 저장하는 상태 레지스터(Status register), 음수 연산을 위한 2의 보수기(2's complementer), 사칙연산을 수행하는 산술 연산기(Arithmetic operator), NOT이나 AND 같은 논리 연산을 수행하는 논리 연산기(Logic operator), 비트 열을 이동시키는 시프트 레지스터(Shift register)가 있습니다.

### Slide 47: ALU의 연산 동작
ALU의 연산이 이루어지는 데이터 흐름을 보여줍니다. 8비트 데이터 버스를 통해 누산기(AC)와 범용 레지스터(B)의 데이터가 임시 레지스터(TEMP1, TEMP2)로 이동한 후 ALU로 입력됩니다. ALU에서 연산이 완료되면 그 결과는 다시 누산기(AC)로 돌아가고, 연산에 대한 상태 정보는 상태 레지스터(flag)에 기록됩니다.

### Slide 48: 명령어 집합 구조 (ISA): CISC vs. RISC
명령어 집합 구조(Instruction Set Architecture, ISA)의 개념과 그 대표적인 두 가지 설계 철학인 CISC와 RISC를 비교하는 새로운 섹션의 시작을 알리는 슬라이드입니다.

### Slide 49: 프로그램 실행의 계층 구조 (How to run your program?)
사용자가 작성한 응용 프로그램이 실제 하드웨어에서 실행되기까지의 계층 구조를 보여줍니다. 최상단의 응용 프로그램과 프로그래밍 언어는 소프트웨어 영역에 속하며, 컴파일러와 운영체제를 거쳐 가장 하단의 디지털 논리 회로와 트랜지스터 같은 물리적 하드웨어 영역으로 변환 및 전달되는 과정을 나타냅니다. 


### Slide 50: 명령어 집합 구조 (ISA)
ISA는 소프트웨어 개발자(컴파일러나 운영체제 개발자 포함)가 볼 수 있는 하드웨어의 추상화된 계층이며, 소프트웨어와 하드웨어 사이의 인터페이스 역할을 합니다. CPU가 어떻게 동작해야 하는지 명시한 일종의 규약 문서로, 명령어의 종류, 인코딩 방식, 레지스터, 데이터 타입, 주소 지정 방식 등을 모두 포함합니다. 인텔의 x86-64가 대표적인 ISA의 예시입니다.

## 설계 철학의 비교: CISC vs. RISC (Slides 51-60)

### Slide 51: ISA의 분류와 레지스터 (Class of ISA)
ISA는 내부 저장소 구조에 따라 분류될 수 있으며, 현대 아키텍처는 주로 범용 레지스터(General-purpose registers)를 사용합니다. 그중 RISC-V는 32개의 범용 레지스터와 32개의 부동소수점 레지스터를 가집니다. 각 레지스터는 항상 0을 반환하는 zero 레지스터부터 복귀 주소, 스택 포인터 등 고유의 명칭과 용도를 명확히 가지고 있습니다.

### Slide 52: ISA의 세부 특성
RISC-V를 기준으로 ISA를 구성하는 세부적인 특성들을 설명합니다. 바이트 단위로 주소를 지정하며, 레지스터나 변위(Displacement)를 이용하는 주소 지정 방식을 채택하고 있습니다. 피연산자의 크기는 8비트부터 64비트까지 다양하게 지원하고, 데이터 전송, 산술 논리 연산, 제어 흐름 등을 제어하는 명령어로 구성되며, 명령어의 길이는 고정된 인코딩 방식을 사용합니다.

### Slide 53: RISC-V 명령어 예시 1 (데이터 전송 및 산술/논리)
교재에 수록된 RISC-V의 실제 명령어들을 보여줍니다. 레지스터와 메모리 간에 데이터를 이동시키는 Load/Store 계열 명령어(데이터 전송)와 덧셈, 뺄셈, 곱셈, 비트 논리 연산, 시프트 연산을 수행하는 명령어(산술/논리)들의 형태와 구체적인 의미를 정리하고 있습니다.

### Slide 54: RISC-V 명령어 예시 2 (제어 및 부동소수점)
앞 슬라이드에 이어, 프로그램의 실행 흐름을 통제하는 조건부 분기(Branch) 및 점프(Jump) 명령어의 작동 방식을 설명합니다. 또한 더블 정밀도(DP) 및 싱글 정밀도(SP) 포맷을 다루는 부동소수점(Floating point) 연산 명령어의 종류와 그 의미를 나열하고 있습니다.

### Slide 55: CISC 구조 (Complex Instruction Set Computers)

CISC는 가능한 한 적은 줄의 어셈블리 코드로 작업을 완료하는 것을 목표로 한 초기 프로세서 설계 철학입니다. 프로그래머가 복잡한 데이터 적재 및 저장 작업을 일일이 지시하지 않아도 되도록, 하드웨어 내부에 복잡한 명령어를 직접 구현했습니다. 그 결과, 프로그램을 저장하는 데 필요한 메모리(RAM) 용량이 적게 들고 컴파일러의 작업 부담이 적다는 장점이 있습니다.

### Slide 56: RISC 구조 (Reduced Instruction Set Computers)
RISC는 복잡한 명령어를 배제하고, 하나의 클럭 사이클 내에 실행 완료될 수 있는 단순한 명령어들로만 구성한 설계 철학입니다. CISC의 곱셈 명령어 하나를 처리하기 위해 RISC는 데이터를 가져오고(Load), 연산하고(Prod), 다시 저장하는(Store) 여러 개의 단순한 명령어로 쪼개어 실행합니다. 이를 통해 하드웨어의 트랜지스터 수를 줄이고 파이프라이닝(Pipelining) 기법을 쉽게 적용할 수 있습니다.

### Slide 57: CISC와 RISC의 특징 비교
CISC와 RISC의 차이를 대조하여 요약합니다. CISC는 복잡한 명령어를 위해 하드웨어에 집중하며, 코드 크기가 작고 메모리에서 메모리로 직접 연산이 가능합니다. 반면 RISC는 소프트웨어(컴파일러)에 집중하며, 고정된 길이의 단순 명령어만 사용하여 코드 크기는 커지지만 클럭 속도를 높일 수 있고 연산은 반드시 레지스터 간에만 이루어집니다.

### Slide 58: CISC와 RISC의 발전 동향
인텔의 x86 라인업은 유연성이 높지만 전력 소모가 큰 CISC를 대표하며, ARM이나 Apple M1 등은 저전력 모바일 환경에 특화된 RISC를 대표합니다. 그러나 현대에 이르러 인텔 프로세서가 내부적으로는 RISC 형태의 명령어로 변환하여 처리하고, ARM 프로세서 역시 복잡한 기능을 흡수하면서 두 구조 간의 명확한 경계는 점차 무의미해지고 있습니다.

### Slide 59: RISC-V 아키텍처
2010년 UC 버클리에서 개발된 최신 RISC 명령어 집합인 RISC-V를 소개합니다. 오픈소스 기반으로 누구나 사용할 수 있으며, 과거 아키텍처들의 한계를 극복하기 위해 풍부한 레지스터, 파이프라인에 최적화된 단순성 등을 특징으로 합니다. 현재 구글, 마이크로소프트, 삼성 등 다수의 글로벌 기업이 참여하는 재단에 의해 유지 관리되고 있습니다.

### Slide 60: 컴퓨터 아키텍처의 현대적 정의
과거에는 컴퓨터 아키텍처를 단순히 명령어 집합 구조(ISA)를 설계하는 것으로 국한하여 보았습니다. 하지만 현대의 실질적인 컴퓨터 아키텍처 설계는 비용, 전력, 가용성이라는 물리적 제약 조건 안에서 성능을 극대화하기 위해 ISA뿐만 아니라 내부의 마이크로아키텍처와 하드웨어 설계 전체를 포괄하는 광범위한 영역으로 정의됩니다.

# 피연산자 위치에 따른 ISA 분류 및 메모리 접근 방식

## 피연산자 위치에 따른 ISA 분류 (Slides 61-66)

### Slide 61: 추상화의 전체 계층 (Full levels of abstraction)
이 슬라이드는 응용 프로그램부터 가장 밑바탕이 되는 물리 및 화학적 소자까지, 컴퓨터 시스템을 구성하는 전체적인 추상화 계층(Abstraction layers)을 보여줍니다. 여기서 붉은색 상자로 강조된 '아키텍처(Architecture, 즉 ISA)'는 소프트웨어 계층(운영체제, 컴파일러 등)과 하드웨어 계층(마이크로아키텍처, 디지털 논리 회로 등)을 이어주는 명확한 경계선이자 인터페이스 역할을 한다는 점을 시각적으로 전달합니다.

### Slide 62: 명령어 집합 구조의 분류 (Classifying instruction set architectures)
명령어 집합 구조(ISA)를 어떻게 분류할 수 있는지 다루는 새로운 소단원의 표지 슬라이드입니다. 교재의 부록 A.2에 해당하는 내용으로, 아키텍처를 설계하는 다양한 철학과 구조적 차이를 학습하게 됩니다.

### Slide 63: 아키텍처를 구분하는 방법
프로세서 내부에서 피연산자(Operand)를 저장하는 방식에 따라 ISA를 분류합니다. 피연산자의 위치를 명령어에 명시적으로 표기하느냐, 아니면 구조적으로 암시되어 있느냐에 따라 다음 세 가지로 나뉩니다.
* **스택(Stack) 아키텍처**: 피연산자를 스택의 최상단(TOS)에서 암시적으로 꺼내어 사용합니다.
* **누산기(Accumulator) 아키텍처**: 하나의 누산기 레지스터를 암시적으로 기준 삼아 사용합니다.
* **범용 레지스터(General-purpose register, GPR) 아키텍처**: 사용할 레지스터를 명시적으로 지정하며, 메모리와 레지스터의 관계에 따라 레지스터-메모리 구조와 로드-스토어 구조로 다시 나뉩니다. 
1980년대 이전의 초기 컴퓨터들은 주로 설계가 단순한 스택이나 누산기 방식을 사용했습니다.

### Slide 64: 연산 아키텍처별 동작 비교
$C=A+B$라는 동일한 덧셈 연산을 네 가지 다른 아키텍처에서 어떻게 처리하는지 단계별 명령어와 다이어그램으로 비교합니다.
* **스택(Stack)**: A와 B를 차례로 스택에 넣고(Push), 더한 뒤(Add), 결과를 빼냅니다(Pop).
* **누산기(Accumulator)**: A를 누산기에 적재하고(Load A), B를 더한 뒤(Add B), 결과를 메모리에 저장합니다(Store C).
* **레지스터-메모리(Register-memory)**: 메모리에 있는 B를 레지스터에 보관된 A와 메모리 접근을 통해 바로 더할 수 있습니다.
* **로드-스토어(Register-register / Load-store)**: A와 B를 각각 별도의 레지스터로 먼저 가져온 뒤에만(Load R1, A 및 Load R2, B) ALU에서 연산을 수행하고(Add R3, R1, R2), 그 결과를 다시 메모리에 저장합니다(Store R3, C).

### Slide 65: 현대 컴퓨터가 로드-스토어 구조를 사용하는 이유
현대의 컴퓨터 아키텍처가 범용 레지스터 기반의 로드-스토어(Load-store) 방식을 표준처럼 채택하게 된 이유를 설명합니다. 가장 핵심적인 이유는 레지스터가 메인 메모리보다 압도적으로 빠르기 때문입니다. 변수들을 빠른 레지스터에 보관해 두고 연산하면 메모리를 오가는 트래픽이 크게 줄어들어 프로그램의 전반적인 실행 속도가 향상됩니다. 또한, 긴 메모리 주소 대신 짧은 레지스터 번호만 명령어에 포함시키면 되므로 코드의 크기(Code density)도 줄일 수 있습니다.

### Slide 66: 범용 레지스터(GPR) 아키텍처의 특성
범용 레지스터를 사용하는 아키텍처를 두 가지 기준을 통해 더 상세히 분류합니다. 첫째는 하나의 산술 연산(ALU) 명령어에 포함될 수 있는 피연산자의 최대 개수(2개 또는 3개)이고, 둘째는 해당 연산 명령어에서 직접 메모리 주소를 지정할 수 있는 횟수(0개에서 3개)입니다. 
예를 들어 ARM, MIPS, RISC-V는 연산 시 메모리 주소를 전혀 사용할 수 없고(0개) 레지스터만 사용하는 전형적인 로드-스토어 구조입니다. 반면 인텔 80x86(x86) 계열은 메모리 주소를 1개 사용할 수 있는 레지스터-메모리 구조로 분류됩니다.

## 메모리 접근 방식: Load-Store 구조의 이해 (Slides 67-69)

### Slide 67: 아키텍처 유형별 장단점
명령어 구조에 따른 장단점을 표로 정리하여 비교합니다.
* **레지스터-레지스터(Load-store)**: 명령어 길이가 고정되어 있고 구조가 단순하여 파이프라이닝에 유리합니다. 실행 클럭수도 일정합니다. 단점으로는 메모리에 접근하기 위한 Load/Store 명령어가 별도로 필요해 프로그램의 전체 명령어 개수(Instruction count)가 많아집니다.
* **레지스터-메모리**: 별도의 Load 없이 메모리 데이터에 접근 가능해 명령어가 간결해집니다. 단점으로는 연산 시 덮어씌워진 소스 피연산자가 파괴될 수 있고, 명령어마다 실행에 걸리는 클럭 수가 달라집니다.
* **메모리-메모리**: 임시 레지스터 낭비 없이 코드가 가장 짧아지지만, 연산마다 발생하는 극심한 메모리 병목 현상 때문에 현대에는 더 이상 사용되지 않습니다.

### Slide 68: 메모리(Load-store) 아키텍처 다이어그램
현대 컴퓨터의 근간이 되는 로드-스토어 구조의 핵심 원리를 명확하게 요약하는 다이어그램입니다. 
왼쪽의 프로세서(Processor) 내부 레지스터(Registers)는 속도가 매우 빠르지만 저장 공간이 제한적입니다. 오른쪽의 메인 메모리(Memory)는 공간이 훨씬 크지만 속도는 상대적으로 느립니다. 이 구조에서 산술 논리 연산 장치(ALU)는 철저하게 프로세서 내부의 레지스터들끼리만 연산을 수행합니다. 프로세서와 메모리 사이의 소통은 데이터를 가져오는 'Load' 명령과 연산 결과를 기록하는 'Store' 명령이라는 제한된 통로를 통해서만 이루어진다는 점을 직관적으로 보여줍니다.
