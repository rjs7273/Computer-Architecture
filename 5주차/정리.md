# 대주제 1: RISC-V 명령어 체계와 피연산자의 기초 (Slide 1~20)

## 소주제 1.1: 하드웨어 기초 및 ISA 복습 (Slide 1~7)

### Slide 1: 타이틀 페이지
이번 강의에서는 컴퓨터의 언어라고 할 수 있는 `명령어(Instructions)`에 대해 본격적으로 학습하겠습니다. 지난 시간에 다루었던 성능 지표와 하드웨어 기본 구조를 바탕으로, 실제 소프트웨어가 하드웨어 위에서 어떻게 동작하는지 그 첫 번째 파트를 시작합니다.

### Slide 2: 목차 (Contents)
이번 단원에서는 크게 네 가지 주제를 다룹니다. 첫째, 컴퓨터의 언어인 `명령어(Instructions)`의 기본 개념을 배웁니다. 둘째, 비트 단위 처리를 위한 `논리 연산(Logical operations)`을 살펴봅니다. 셋째, 우리가 작성한 명령어가 컴퓨터 내부에서 어떻게 `표현(Representing instructions)`되는지 학습하며, 마지막으로 프로그램의 흐름을 제어하는 `의사결정 명령어(Instructions for making decisions)`를 다루게 됩니다.

### Slide 3: (Recall) CPU 클로킹 (CPU Clocking)
본격적인 학습에 앞서 CPU의 동작 원리를 복습해 봅시다. 디지털 하드웨어는 일정한 간격의 `클록(Clock)`에 맞춰 동작합니다. 성능을 개선하기 위해서는 실행에 필요한 `클록 사이클(Clock cycles)`의 수를 줄이거나, `클록 속도(Clock rate)`를 높여야 합니다. 하드웨어 설계자는 보통 이 두 요소 사이에서 적절한 절충안을 찾아야 합니다. CPU 시간 계산 공식은 다음과 같습니다.


$CPU\ Time = CPU\ Clock\ Cycles \times Clock\ Cycle\ Time$


$CPU\ Time = \frac{CPU\ Clock\ Cycles}{Clock\ Rate}$

### Slide 4: (Recall) 명령어 집합 구조의 분류 (Classifying instruction set archit.)
데이터를 처리하는 핵심 공간인 `레지스터(Register)`를 복습하겠습니다. 레지스터는 CPU 내부에서 아주 적은 양의 데이터를 매우 빠르게 저장하기 위한 부품입니다. 본 강의에서는 32비트 레지스터를 사용하는 `RV32` 모델을 기준으로 설명합니다. RISC-V의 기본 `ISA(Instruction Set Architecture)`는 32개의 `범용 레지스터(General-purpose registers, GPR)`를 가지며, 이들은 `x1`부터 `x31`까지 번호가 붙어 있습니다. 특히 `x0` 레지스터는 항상 0이라는 값이 하드웨어적으로 고정되어 있다는 점이 중요합니다.

### Slide 5: (Recall) RISC-V는 로드-스토어 구조 (Load-store architecture)
RISC-V의 가장 큰 특징 중 하나는 `로드-스토어 구조(Load-store architecture)`라는 점입니다. 과거의 다양한 구조(스택, 누산기, 레지스터-메모리 등)와 달리, RISC-V는 연산을 수행할 때 반드시 데이터를 메모리에서 레지스터로 가져온(`Load`) 후, 레지스터끼리 연산하고 그 결과를 다시 메모리에 저장(`Store`)하는 방식을 취합니다. 이는 하드웨어 구현을 단순하게 만들어 성능을 높이는 데 유리합니다.

### Slide 6: (Recall) 레지스터와 로드-스토어의 관계 (Register (Load-store))
이 그림은 프로세서와 메모리 간의 관계를 시각적으로 보여줍니다. 프로세서 내부의 `데이터패스(Datapath)`에는 `프로그램 카운터(PC)`, `레지스터`, 그리고 실제 연산을 담당하는 `산술 논리 장치(ALU)`가 포함됩니다. 레지스터는 공간은 한정적이지만 속도가 매우 빠르고, 메모리는 공간은 넓지만 상대적으로 속도가 느립니다. 따라서 효율적인 프로그래밍을 위해서는 자주 사용하는 데이터를 최대한 레지스터에 머물게 하는 것이 핵심입니다.

### Slide 7: (Recall) CPU와 메모리의 상호작용 (CPU and memory)
마지막으로 전체 시스템 관점에서의 복습입니다. `프로세싱 유닛(Processing unit)`인 CPU는 메모리에 `주소(Address)`를 보내 `명령어(Instruction)`를 가져오고, 필요한 `데이터(Data)`를 읽거나 씁니다. 메모리는 바이트 단위로 주소가 지정되는 `바이트 주소 지정 가능 배열(Byte addressable array)`로 취급됩니다. CPU는 데이터 이동, 산술 및 논리 연산, 그리고 제어 흐름의 이동을 통해 프로그램을 실행해 나갑니다.


## 소주제 1.2: RISC-V 명령어 개요 및 설계 원칙 (Slide 8~12)

### Slide 8: 컴퓨터의 언어: 명령어 (Instructions: Language of the Computer)
이제 본격적으로 교재의 2장 내용인 `명령어(Instructions)`를 학습하겠습니다. 명령어는 인간이 하드웨어에 내리는 구체적인 명령이자, 하드웨어가 이해할 수 있는 유일한 언어입니다. 우리가 작성하는 고수준 언어(C, Java 등)가 결국 하드웨어 수준에서 어떻게 해석되는지 이해하는 것이 이번 단원의 목표입니다.

### Slide 9: RISC-V 명령어 개요 (RISC-V instruction: overview)
RISC-V 명령어의 기본 형식을 살펴보겠습니다. RISC-V 어셈블리 코드의 각 줄은 하나의 `명령어`에 대응합니다. 산술, 논리, 시프트 및 분기 명령어는 일반적으로 3개의 `피연산자(Operands)`를 가집니다. 보통 2개의 소스(Source)와 1개의 목적지(Destination)로 구성됩니다. 데이터 전송이나 무조건 분기는 2개의 피연산자를 사용하기도 합니다. 여기서 우리는 제1 설계 원칙인 `Simplicity favors regularity(단순함은 규칙성을 선호한다)`를 엿볼 수 있습니다. 규칙적인 구조는 하드웨어 구현을 단순하게 만들고, 단순함은 낮은 비용으로 높은 성능을 낼 수 있게 합니다.

### Slide 10: 컴파일 사례: 정렬 함수 (RISC-V instruction: overview - Compiler)
고수준 언어인 C 코드가 실제 RISC-V 어셈블리로 어떻게 변환되는지 보여주는 예시입니다. 왼쪽의 `sort` 함수는 루프와 조건문을 포함하고 있습니다. 이를 `컴파일러(Compiler)`가 번역하면 오른쪽과 같은 복잡한 어셈블리 코드가 생성됩니다. 여기서 `Loop1`, `Loop2`, `Exit`와 같은 `레이블(Label)`을 통해 프로그램의 흐름이 제어되며, 스택 포인터(`sp`)를 조절하거나 레지스터에 값을 저장하는 과정을 볼 수 있습니다. 처음에는 복잡해 보이지만, 결국 우리가 배울 개별 명령어들의 조합일 뿐입니다.

### Slide 11: RISC-V 명령어 요약 표 (RISC-V instruction: overview – Cont’d)
이 표는 RISC-V의 주요 명령어들을 카테고리별로 요약한 `명령어 집합(Instruction Set)` 명세입니다. 산술(`Arithmetic`), 데이터 전송(`Data transfer`), 논리(`Logical`), 시프트(`Shift`), 조건부 분기(`Conditional branch`), 무조건 분기(`Unconditional branch`)로 나뉩니다. 각 명령어의 구문(Syntax)과 의미(Meaning), 그리고 간단한 설명을 담고 있습니다. 앞으로 우리가 배우게 될 모든 명령어의 기초가 되는 지도와 같은 표이므로 자주 참조하게 될 것입니다.

### Slide 12: 명령어 주석 (RISC-V instruction: Comments)
어셈블리 언어에서 `주석(Comments)`은 다른 언어보다 훨씬 더 중요합니다. RISC-V에서는 `#` 기호를 사용하며, 기호 이후의 내용은 파이썬처럼 무시됩니다. 어셈블리 코드에는 `변수 이름(Variable names)`이 전혀 존재하지 않고 오직 레지스터 번호나 메모리 주소만 나타나기 때문에, 각 줄이 어떤 논리적 의미를 갖는지 주석으로 기록해두지 않으면 코드를 해독하기가 매우 어렵습니다. 따라서 좋은 어셈블리 코딩 습관은 상세한 주석에서 시작됩니다.

## 소주제 1.3: 산술 연산과 데이터 피연산자 (Slide 13~20)

### Slide 13: RISC-V 산술 명령어 (RISC-V arithmetic instruction)
RISC-V의 모든 산술 명령어는 반드시 3개의 피연산자를 가져야 합니다. 구체적으로는 결과를 저장할 1개의 `목적지(Destination)`와 계산의 대상이 되는 2개의 `소스(Sources)`로 구성됩니다. 예를 들어 C 언어에서 $a = b + c$라는 코드를 작성하면, RISC-V에서는 `add a, b, c`와 같은 형식을 취합니다. 만약 변수 $a, b, c$가 각각 레지스터 `x5, x6, x7`에 할당되어 있다면, 실제 명령어는 `add x5, x6, x7`이 됩니다. 뺄셈 또한 동일한 형식을 유지하며, 이는 명령어 구조를 일관되게 유지하려는 설계 철학을 보여줍니다.

### Slide 14: 여러 개의 소스 변수 처리 (RISC-V arithmetic instruction – Cont’d)
만약 소스 피연산자가 2개보다 많은 복잡한 수식은 어떻게 처리할까요? 하드웨어는 한 번에 두 개의 값만 연산할 수 있으므로, 컴파일러는 복잡한 수식을 여러 개의 단순한 명령어로 쪼개게 됩니다. 예를 들어 $a = b + c + d + e$라는 식은 세 번의 `add` 명령어로 나누어 실행됩니다. 또한 $f = (g + h) - (i + j)$와 같이 괄호가 포함된 식은 중간 결과값을 저장하기 위해 `t0, t1`과 같은 `임시 레지스터(Temporary registers)`를 사용하여 단계적으로 계산합니다. 결국 모든 복잡한 연산은 기본 산술 명령어의 조합으로 환원됩니다.

### Slide 15: 레지스터 피연산자 (Register operands)
산술 연산은 CPU 내부의 `레지스터(Registers)`를 직접 피연산자로 사용합니다. RISC-V는 32비트 크기의 레지스터 32개를 모아놓은 `레지스터 파일(Register file)`을 가지고 있습니다. 32비트 데이터를 `워드(Word)`라고 부르며, 64비트 데이터는 `더블워드(Doubleword)`라고 합니다. 여기서 제2 설계 원칙인 `Smaller is faster(작은 것이 더 빠르다)`가 등장합니다. 수백만 개 이상의 위치를 가진 메인 메모리보다, 단 32개뿐인 레지스터에 접근하는 것이 전기 신호 전달 거리가 짧아 훨씬 빠르기 때문입니다. 따라서 자주 사용하는 데이터는 반드시 레지스터에 두고 연산해야 성능을 보장할 수 있습니다.

### Slide 16: 메모리 피연산자 (Memory operands)
배열이나 구조체와 같이 데이터의 양이 많은 `복합 데이터(Composite data)`는 레지스터에 다 담을 수 없으므로 `메인 메모리(Main memory)`에 저장합니다. 메모리에 있는 데이터를 연산하려면 먼저 `Load` 명령어로 메모리 값을 레지스터로 가져와야 하고, 연산이 끝난 후에는 `Store` 명령어로 결과를 다시 메모리에 기록해야 합니다. RISC-V 메모리는 8비트 단위로 주소를 매기는 `바이트 주소 지정(Byte addressed)` 방식을 사용하며, 낮은 주소에 데이터의 하위 바이트를 저장하는 `리틀 엔디언(Little endian)` 방식을 채택하고 있습니다.

### Slide 17: 엔디언 방식 비교 (Memory operands – Cont’d)
데이터를 메모리에 배치하는 방식은 크게 두 가지입니다. `빅 엔디언(Big-endian)`은 데이터의 최상위 바이트(MSB)를 가장 낮은 주소에 저장하는 방식이고, `리틀 엔디언(Little-endian)`은 데이터의 최하위 바이트(LSB)를 가장 낮은 주소에 저장하는 방식입니다. 그림 (a)의 $0xA0B0C0D0$라는 4바이트 데이터를 예로 들면, 빅 엔디언은 주소 $0$번에 $0xA0$를 두지만, 리틀 엔디언은 $0xD0$를 둡니다. RISC-V는 리틀 엔디언을 표준으로 사용하므로 주소 체계를 이해할 때 이를 반드시 고려해야 합니다.

### Slide 18: 메모리 주소 지정 예시 (Memory operands – Cont’d)
실제 C 코드가 어떻게 컴파일되는지 살펴보겠습니다. $A[12] = h + A[8]$이라는 코드가 있을 때, 배열 $A$의 시작 주소(Base address)가 `x22`에 있고 $h$가 `x21`에 있다면, 먼저 $A[8]$의 값을 읽어와야 합니다. 더블워드(8바이트) 기준이라면 인덱스 8은 $8 \times 8 = 64$바이트만큼 떨어진 곳이므로 `ld x9, 64(x22)` 명령어를 실행합니다. 여기서 `x22`를 `베이스 레지스터(Base register)`, `64`를 `오프셋(Offset)`이라고 부릅니다. 이후 덧셈을 수행하고, 결과인 $A[12]$를 저장하기 위해 오프셋 $12 \times 8 = 96$을 사용하여 `sd x9, 96(x22)` 명령어를 실행하게 됩니다.

### Slide 19: 레지스터와 메모리의 성능 차이 (Registers vs. Memory)
레지스터는 메모리보다 훨씬 빠르고 효율적입니다. 2020년 기술 기준으로 레지스터는 DRAM(메인 메모리)보다 약 200배 빠르고, 에너지 효율은 10,000배나 더 높습니다. 메모리 데이터를 직접 연산할 수 없으므로 `Load`와 `Store` 명령어가 추가로 필요하며, 이는 곧 실행할 명령어 수가 늘어남을 의미합니다. 따라서 컴파일러는 최대한 많은 변수를 레지스터에 할당하려 노력하며, 레지스터가 부족해 메모리로 데이터를 내보내는 `스필링(Spilling)` 현상을 최소화하는 `레지스터 최적화(Register optimization)`가 매우 중요합니다.

### Slide 20: 상수 또는 즉치 피연산자 (Constant or Immediate Operands)
프로그램을 작성하다 보면 $i++$와 같이 상수를 사용하는 경우가 매우 많습니다. 상수를 매번 메모리에서 가져오는 것은 비효율적이므로, 명령어 자체에 값을 포함시키는 `즉치(Immediate)` 피연산자를 사용합니다. `addi x22, x22, 4`와 같이 사용하면 별도의 로드 과정 없이 즉시 4를 더할 수 있습니다. 이는 "자주 발생하는 케이스를 빠르게 만든다(Make the common case fast)"는 설계 철학을 반영한 것입니다. 또한 `x0` 레지스터는 항상 0으로 고정되어 있어, 상수가 필요한 다양한 연산에서 매우 유용하게 활용됩니다.

# 대주제 2: 논리 연산과 명령어의 내부 표현 (Slide 21~38)

## 소주제 2.1: 비트 단위 논리 연산 (Slide 21~26)

### Slide 21: 논리 연산 시작 (Logical operations)
이제 교재 2.5장에 해당하는 `논리 연산(Logical operations)` 단원을 시작하겠습니다. 산술 연산이 숫자의 크기를 다룬다면, 논리 연산은 데이터 내부의 개별 비트를 직접 제어하는 데 목적이 있습니다. 프로그래밍에서 데이터를 압축하거나 특정 플래그를 확인할 때 필수적으로 사용되는 기술입니다.

### Slide 22: 비트 조작을 위한 명령어 (Logical operations - Table)
컴퓨터는 단어(Word) 내에서 특정 비트 그룹을 `추출(Extracting)`하거나 `삽입(Inserting)`해야 할 때가 많습니다. 이를 위해 시프트(Shift), AND, OR, XOR, NOT과 같은 명령어들을 제공합니다. 표를 보시면 C나 Java에서 사용하는 연산자(`<<`, `&`, `|` 등)가 RISC-V의 `sll`, `and`, `or` 등과 일대일로 대응되는 것을 알 수 있습니다. 특히 RISC-V에는 별도의 `NOT` 명령어가 없는데, 이는 `xori` 명령어를 활용해 구현할 수 있기 때문입니다.

### Slide 23: 시프트 연산 (Shift operations)
`시프트 연산(Shift operations)`은 비트들을 왼쪽이나 오른쪽으로 밀어내는 동작을 합니다. `slli(Shift Left Logical Immediate)`는 비트를 왼쪽으로 $i$만큼 밀고 빈자리를 0으로 채우는데, 이는 결과적으로 값에 $2^i$를 곱하는 효과를 줍니다. 반대로 `srli(Shift Right Logical Immediate)`는 비트를 오른쪽으로 밀어 0으로 채우며, $2^i$로 나누는 효과(부호 없는 정수 기준)를 냅니다. 명령어 구조에서 `immed` 필드는 비트를 몇 칸 옮길지를 결정하는 6비트 값을 담고 있습니다.

### Slide 24: AND 연산 (AND operation)
`AND 연산`은 두 비트가 모두 1일 때만 결과가 1이 됩니다. 이 연산은 주로 특정 비트들만 선택하고 나머지는 0으로 지워버리는 `마스킹(Masking)` 작업에 사용됩니다. 예시를 보면 `x11` 레지스터를 마스크로 사용하여 `x10`의 특정 부분만 남기고 나머지는 모두 0으로 만든 것을 확인할 수 있습니다. 마치 체처럼 원하는 비트만 걸러내는 역할을 한다고 이해하시면 됩니다.

### Slide 25: OR 연산 (OR operation)
`OR 연산`은 두 비트 중 하나라도 1이면 결과가 1이 됩니다. 이는 단어 내에 특정 비트들을 강제로 1로 설정할 때 유용하며, 이를 비트를 `포함(Include)`시킨다고 표현합니다. 마스크로 사용하는 비트가 1인 자리는 결과값이 무조건 1이 되고, 0인 자리는 원래 `x10`의 값을 그대로 유지하게 됩니다. 데이터의 특정 설정을 켜는(Set) 작업에 주로 활용됩니다.

### Slide 26: XOR 연산 (XOR operation)
`XOR 연산`은 두 비트가 서로 다를 때만 1을 반환하는 `차이(Differencing)` 연산입니다. 만약 어떤 값을 모든 비트가 1인 마스크와 XOR 연산하면, 원래 비트가 0인 것은 1로, 1인 것은 0으로 뒤집히게 됩니다. 슬라이드의 예시처럼 `x11`을 모두 1로 채워 연산하면 비트가 반전되는 효과를 얻을 수 있습니다. 앞서 언급했듯이 RISC-V에서 비트 반전(NOT) 기능을 수행하고 싶을 때 이 `xor` 혹은 `xori` 명령어를 사용합니다.

## 소주제 2.2: 명령어 포맷의 구조 분석 (R, I, S-type) (Slide 27~34)

### Slide 27: 컴퓨터 내의 명령어 표현 (Representing instructions in the computer)
이제 우리가 지금까지 살펴본 어셈블리 명령어가 컴퓨터 하드웨어 내부에서 실제로 어떻게 저장되는지 알아보겠습니다. 컴퓨터는 결국 0과 1의 조합만을 이해할 수 있습니다. 우리가 텍스트로 작성한 `add`나 `sub` 같은 명령어들도 실제로는 일정한 규칙에 따라 이진수 숫자로 변환되어 메모리에 저장됩니다.

### Slide 28: RISC-V 명령어 포맷과 R-type (RISC-V instruction format)
RISC-V의 모든 명령어는 하드웨어 설계의 제1 원칙인 '규칙성'을 지키기 위해 예외 없이 `32비트(32 bits)` 길이를 가집니다. 명령어의 비트들이 어떻게 나뉘어 배치되는지를 `명령어 포맷(Instruction format)`이라고 합니다. 가장 기본이 되는 `R-type(Register-type)` 포맷은 총 6개의 필드로 구성됩니다. `opcode`(7비트)는 연산의 종류를 결정하고, `rd`(5비트)는 결과가 저장될 목적지 레지스터 번호입니다. `rs1`과 `rs2`(각 5비트)는 소스 레지스터 번호이며, `funct3`와 `funct7`은 `opcode`를 보조하여 구체적인 연산(예: add인지 sub인지)을 지정하는 추가 코드입니다.

### Slide 29: R-type 명령어 변환 예시 (RISC-V instruction format – Cont’d)
`add x9, x20, x21`이라는 명령어가 실제 숫자로 변환되는 과정을 봅시다. `add` 연산의 `opcode`는 51(0110011)이고, `rd`는 9, `rs1`은 20, `rs2`는 21입니다. 이 숫자들을 이진수로 변환하여 각 필드에 채워 넣으면 하나의 32비트 숫자가 완성됩니다. 이 긴 이진수는 읽기 불편하므로 보통 8자리의 `16진수(Hexadecimal)`인 $015A04B3_{16}$으로 표현합니다. 하단 표는 이진수와 16진수 간의 변환 관계를 보여줍니다.

### Slide 30: I-type 명령어 포맷 (RISC-V I-type format Instructions)
상수를 사용하는 `addi`나 메모리에서 값을 가져오는 `lw` 같은 명령어는 `rs2` 레지스터 번호가 필요 없습니다. 대신 상숫값이 들어갈 공간이 필요하죠. 만약 R-type의 5비트 필드(`rs2`)만 상수로 쓰기엔 표현할 수 있는 숫자의 범위가 너무 작습니다. 그래서 `funct7`과 `rs2` 필드를 하나로 합쳐 12비트 크기의 `immediate(즉치)` 필드를 만든 것이 `I-type` 포맷입니다. 여기서 제3 설계 원칙인 `Good design demands good compromises(좋은 설계는 좋은 절절한 절충안을 요구한다)`를 볼 수 있습니다. 포맷이 여러 개면 복잡해지지만, 대신 모든 명령어를 32비트라는 동일한 길이로 유지할 수 있게 됩니다.

### Slide 31: S-type 명령어 포맷 (RISC-V S-type format Instructions)
메모리에 데이터를 저장하는 `sw(store word)` 명령어는 조금 독특합니다. 저장할 값(데이터)이 들어있는 `rs2`와 베이스 주소가 들어있는 `rs1`은 필요하지만, 결과값을 담을 목적지 레지스터(`rd`)는 필요하지 않습니다. 이때 하드웨어 해독 장치를 단순하게 만들기 위해 `rs1`과 `rs2` 필드의 위치를 R-type과 동일하게 유지하는 결정을 내립니다. 그 결과, 12비트 상수는 `immediate[11:5]`와 `immediate[4:0]` 두 부분으로 쪼개져 배치되는데, 이를 `S-type` 포맷이라고 부릅니다.

### Slide 32: R, I, S 타입 포맷 비교 (RISC-V [R, I, S]-type instruction formats)
지금까지 배운 세 가지 주요 포맷을 한눈에 비교해 보겠습니다. `R-type`은 모든 피연산자가 레지스터인 경우(add, sub 등)에 사용됩니다. `I-type`은 상수가 포함된 연산이나 메모리 로드 명령어에 사용되며 12비트 상수를 가집니다. `S-type`은 메모리 저장 명령어 전용으로, 상수가 두 조각으로 나뉘어 들어갑니다. 각 포맷이 서로 다른 목적을 가지면서도 `opcode`, `rs1`, `funct3` 등의 위치를 최대한 일치시켜 하드웨어가 명령어를 빠르게 해석할 수 있도록 설계되었음을 알 수 있습니다.

### Slide 33: 실제 코드의 포맷 분석 예시 (Example: R, I, S-type)
$A[30] = h + A[30] + 1$이라는 복합적인 C 코드가 어떻게 명령어들로 쪼개지고, 각 명령어가 어떤 포맷을 갖는지 보여주는 사례입니다. 먼저 데이터를 가져오는 `lw`는 `I-type`입니다. 그다음 변수 $h$를 더하는 `add`는 `R-type`이고, 상수 1을 더하는 `addi`는 다시 `I-type`이 됩니다. 마지막으로 최종 결과를 메모리에 저장하는 `sw`는 `S-type` 포맷을 가집니다. 각 명령어 줄 아래에는 실제 필드에 들어갈 십진수 값들이 명시되어 있어 포맷 구조를 실질적으로 이해하는 데 도움을 줍니다.

### Slide 34: 다양한 RISC-V 명령어 포맷 (Various RISC-V instruction formats)
RISC-V에는 R, I, S 외에도 몇 가지 포맷이 더 존재합니다. 조건부 분기를 위한 `SB-type`(또는 B-type), 큰 상수를 다루기 위한 `U-type`, 그리고 함수 호출이나 점프를 위한 `UJ-type`(또는 J-type)이 그것입니다. 오른쪽 표는 우리가 흔히 접하는 명령어들이 각각 어떤 포맷에 속하는지를 일목요연하게 정리해 놓았습니다. 예를 들어 `beq`는 SB-type, `jal`은 UJ-type임을 알 수 있습니다. 이로써 RISC-V의 모든 명령어가 규칙적인 몇 가지 틀 안에서 관리됨을 확인하였습니다.


## 소주제 2.3: 내장 프로그램 개념과 실행 흐름 (Slide 35~38)

### Slide 35: 고수준 언어에서 기계어까지의 흐름 (Overall flow from high-level to machine lv.)
우리가 작성한 코드가 실제 하드웨어에서 실행되기까지의 전체 과정을 살펴보겠습니다. 먼저 `C`와 같은 `고수준 언어(High-level language)`로 작성된 프로그램은 `컴파일러(Compiler)`를 통해 `어셈블리어(Assembly language)`로 번역됩니다. 이 어셈블리어는 다시 `어셈블러(Assembler)`에 의해 `0`과 `1`로 이루어진 `이진 기계어(Binary machine language)`가 됩니다. 슬라이드의 `swap` 함수 예시를 보면, 짧은 고수준 코드 한 줄이 여러 개의 기계어 비트 열로 변환되어 컴퓨터가 이해할 수 있는 최종 형태가 되는 것을 알 수 있습니다.

### Slide 36: 내장 프로그램 개념 (The stored-program concept)
오늘날 모든 현대식 컴퓨터의 근간이 되는 `내장 프로그램(Stored-program)` 원리를 이해하는 것은 매우 중요합니다. 이 원리는 두 가지 핵심 원칙을 가집니다. 첫째, `명령어`는 데이터와 마찬가지로 이진 숫자로 표현됩니다. 둘째, `프로그램`은 메모리에 저장되어 필요할 때마다 읽거나 쓸 수 있습니다. 즉, 명령어와 데이터가 동일하게 메모리라는 공간에 숫자로 저장되기에 프로그램을 아주 쉽고 빠르게 교체하거나 수정할 수 있게 된 것입니다. 이 혁신적인 개념 덕분에 컴퓨터는 하나의 하드웨어로 문서 작성, 게임, 계산 등 무궁무진한 작업을 수행하는 범용적인 도구가 되었습니다.

### Slide 37: 프로그램의 메모리 구조 (Program structure)
메모리에 저장된 프로그램은 크게 두 가지 영역으로 나뉩니다. 첫 번째는 `텍스트(Text) 또는 코드 섹션`으로, 실제 실행될 이진 명령어들이 담겨 있습니다. 두 번째는 `데이터 섹션`으로, 프로그램이 실행되는 동안 필요로 하는 각종 이진 데이터들이 저장됩니다. 프로세서 내부의 `제어부(Control)`는 메모리의 텍스트 영역에서 명령어를 인출(Fetch)해오고, `데이터패스(Datapath)`는 데이터 영역과 값을 주고받으며 연산을 수행합니다. 이처럼 프로그램은 메모리라는 거대한 배열 안에서 명령어와 데이터가 체계적으로 배치된 구조를 가집니다.

### Slide 38: 프로세서의 명령어 처리 과정 (Processor)
프로세서가 메모리에 있는 명령어를 어떻게 순차적으로 실행하는지 그 메커니즘을 보겠습니다. 핵심은 `프로그램 카운터(PC, Program Counter)`라는 특수 레지스터입니다. `PC`는 다음에 실행할 명령어의 주소를 가리키고 있습니다. 프로세서의 동작은 크게 4단계로 순환합니다. 1단계는 `인출(Fetch)`로, `PC`가 가리키는 주소의 명령어를 메모리에서 가져옵니다. 2단계는 `해독(Decode)`으로, 이 명령어가 어떤 동작을 하는지 분석합니다. 3단계는 `실행(Execute)`으로, 산술 연산이나 메모리 접근 등을 수행합니다. 마지막 4단계는 `PC 업데이트`로, 현재 명령어의 크기(보통 4바이트)만큼 주소를 더해 다음 명령어를 가리키게 합니다. 이 과정이 끊임없이 반복되며 프로그램이 구동됩니다.

# 대주제 3: 제어 흐름과 의사결정 명령어 (Slide 39~50)

## 소주제 3.1: 조건부 분기 명령어 (Slide 39~44)

### Slide 39: 의사결정 명령어 시작 (Instructions for making decisions)
이제 교재 2.7장에 해당하는 `의사결정 명령어(Instructions for making decisions)` 단원을 학습하겠습니다. 지금까지 배운 산술 연산이나 데이터 전송은 정해진 순서대로만 실행되는 단순한 구조였습니다. 하지만 프로그램이 똑똑하게 동작하려면 상황에 따라 실행 경로를 바꾸는 능력이 필요합니다. 이번 장에서는 컴퓨터가 어떻게 '판단'하고 '분기'하는지 그 핵심 원리를 다룹니다.

### Slide 40: C 언어의 제어 흐름 구조 (Control flow structures in C)
우리가 사용하는 C 언어에는 크게 네 가지 제어 흐름이 있습니다. 첫째는 위에서 아래로 차례대로 실행되는 `순차(Sequential)` 구조입니다. 둘째는 `if-else`나 `switch` 같은 `선택 및 의사결정(Selection/Decision)` 구조입니다. 셋째는 `while`이나 `for` 루프 같은 `반복(Repetition/Loop)` 구조이며, 마지막으로 `break`나 `return` 같은 `점프(Jump)` 구조가 있습니다. 하드웨어 수준의 명령어도 결국 이 복잡한 고수준 구조들을 구현할 수 있도록 설계되어 있습니다.

### Slide 41: C 언어의 goto 문 (goto statement in C)
어셈블리 언어의 분기 원리를 이해하기 위해 C 언어의 `goto` 문을 먼저 살펴보겠습니다. `goto` 문은 프로그램의 제어 흐름을 지정된 `레이블(label)`로 즉시 전송하는 역할을 합니다. 여기서 레이블은 코드 내의 특정 위치를 가리키는 `식별자(identifier)`입니다. 프로그램 실행 중 `goto label;`을 만나면, 중간의 코드를 건너뛰고 `label:`이 위치한 곳부터 다시 실행을 시작합니다. 어셈블리의 모든 분기 명령어는 기본적으로 이 `goto` 방식과 유사하게 동작합니다.

### Slide 42: 조건부 분기 명령어 종류 (Conditional branch instruction)
`조건부 분기(Conditional branch)`는 특정 조건을 테스트한 결과에 따라 프로그램의 주소를 이동시키는 명령어입니다. RISC-V는 네 가지 기본 분기 명령어를 제공합니다. `beq(Branch if equal)`는 두 레지스터 값이 같을 때 분기하고, `bne(Branch if not equal)`는 다를 때 분기합니다. 크기를 비교할 때는 `blt(Branch if less than)`를 사용하여 작을 때 분기하고, `bge(Branch if greater or equal)`를 사용하여 크거나 같을 때 분기합니다. 슬라이드의 예시처럼 C 언어의 `if (a == b) goto L1`은 RISC-V에서 `beq x5, x6, L1`과 같이 명료하게 표현됩니다.

### Slide 43: 부호 있는 수와 없는 수의 비교 (Conditional branch instruction – Signed/Unsigned)
데이터를 비교할 때는 그 데이터가 `부호가 있는 수(Signed)`인지 `부호가 없는 수(Unsigned)`인지 명확히 구분해야 합니다. 기본 명령어인 `blt`와 `bge`는 레지스터의 값을 `2의 보수(two’s complement)` 방식의 부호 있는 정수로 간주하여 비교합니다. 반면, 맨 뒤에 `u`가 붙은 `bltu`와 `bgeu` 명령어는 값을 부호가 없는 양의 정수로 취급합니다. 같은 비트 패턴이라도 부호 여부에 따라 비교 결과가 완전히 달라질 수 있으므로, 데이터의 성격에 맞는 적절한 명령어를 선택하는 것이 매우 중요합니다.

### Slide 44: if-else 문 컴파일 예시 (Example: if-else statement)
실제 `if-else` 문이 어셈블리로 어떻게 번역되는지 분석해 봅시다. `if (d == e) a = b + c; else a = d - e;`라는 코드가 있을 때, 컴파일러는 먼저 조건을 반대로 뒤집어 생각합니다. 즉, `d != e`이면 `Else` 레이블로 가라는 `bne x22, x23, Else` 명령어를 먼저 배치합니다. 만약 조건이 맞다면(같다면) 바로 다음 줄의 `add` 연산을 수행하고, `else` 부분을 건너뛰기 위해 `beq x0, x0, Exit`를 사용합니다. 여기서 `x0`은 항상 0이므로 이는 무조건 `Exit`로 점프하라는 의미입니다. `Else` 레이블 뒤에는 실제 `else` 블록인 `sub` 연산을 배치하여 전체적인 선택 구조를 완성합니다.

# 대주제 3: 제어 흐름과 의사결정 명령어 (Slide 39~50)

## 소주제 3.2: 반복문 구현과 주소 지정 방식 (Slide 45~50)

### Slide 45: while 문 컴파일 예시 (Example: while statement)
C 언어의 반복문인 `while (save[i] == k) i += 1;`을 RISC-V 어셈블리로 번역하는 과정을 살펴보겠습니다. 배열 `save`의 시작 주소는 `x25`, 인덱스 $i$는 `x22`, 비교 대상 $k$는 `x24`에 있다고 가정합니다. 먼저 배열 요소에 접근하기 위해 $i \times 4$를 수행하는 `slli x10, x22, 2` 명령어가 필요합니다. 4를 곱하는 이유는 각 워드 데이터가 4바이트 크기이기 때문입니다. 이후 베이스 주소와 합쳐 `lw x9, 0(x10)`으로 데이터를 가져온 뒤, `bne x9, x24, Exit`를 통해 값이 다르면 루프를 종료합니다. 조건이 맞다면 `addi x22, x22, 1`로 $i$를 증가시키고 `beq x0, x0, Loop`를 통해 다시 루프의 처음으로 돌아갑니다.

### Slide 46: 기본 블록 (Basic Blocks)
컴파일러 최적화와 프로세서 성능 향상에 매우 중요한 개념인 `기본 블록(Basic Block)`을 정의하겠습니다. 기본 블록은 중간에 다른 곳으로 빠져나가는 `분기(branch)`가 없고(단, 블록 맨 끝에는 가능), 외부에서 블록 중간으로 들어오는 `분기 타겟(branch target)`도 없는(단, 블록 맨 처음은 가능) 명령어들의 순차적 묶음입니다. 컴파일러는 이 기본 블록 단위를 식별하여 코드를 최적화하며, 현대의 고성능 프로세서는 이 블록들을 더 빠르게 실행하기 위한 다양한 하드웨어 기술을 사용합니다.

### Slide 47: PC 상대 주소 지정 (PC-relative addressing)
`PC 상대 주소 지정(PC-relative addressing)`은 명령어 내의 상수를 현재 `프로그램 카운터(PC)` 값에 더하여 실제 주소를 결정하는 방식입니다.
$memory\ address = PC\ address + offset$
이 방식은 프로그램이 메모리의 어느 위치에 로드되더라도 동일하게 동작할 수 있게 해줍니다. 즉, 점프할 위치가 현재 명령어로부터 얼마나 떨어져 있는지를 `오프셋(offset)`으로 표현하므로, 프로그램 전체의 절대적인 위치가 바뀌어도 상대적인 거리는 변하지 않기 때문입니다. 이는 `베이스 주소 지정(base addressing)`의 특수한 사례로 볼 수 있으며, 이때 베이스는 일반 레지스터가 아닌 `PC`가 됩니다.

### Slide 48: 네 가지 주소 지정 방식 요약 (PC-relative addressing – Cont’d)
RISC-V에서 사용하는 네 가지 핵심 주소 지정 방식을 정리한 그림입니다. 
1. `즉치 주소 지정(Immediate addressing)`은 피연산자가 명령어 내에 상수로 포함됩니다. 
2. `레지스터 주소 지정(Register addressing)`은 피연산자가 레지스터 내에 있습니다. 
3. `베이스 주소 지정(Base addressing)`은 레지스터 값에 상수를 더해 메모리 주소를 결정하며, `lw`나 `sw` 명령어에서 사용됩니다. 
4. `PC 상대 주소 지정(PC-relative addressing)`은 `PC` 값에 상수를 더해 분기 목적지 주소를 결정하며, 조건부 분기에서 사용됩니다. 하드웨어는 이처럼 다양한 경로를 통해 필요한 데이터나 명령어의 위치를 찾아냅니다.

### Slide 49: 무조건 분기 명령어 (Unconditional branch instruction)
조건에 상관없이 프로그램의 흐름을 다른 주소로 옮기는 `무조건 분기(Unconditional branch)` 명령어를 학습하겠습니다. 가장 대표적인 명령어는 `jal(Jump and Link)`입니다. `jal x1, 128`은 128바이트 떨어진 주소로 점프하면서, 돌아올 주소(현재 PC + 4)를 `x1` 레지스터에 기록합니다. 이는 함수 호출에 필수적입니다. 반면 `jalr(Jump and Link Register)`은 레지스터에 저장된 주소로 점프합니다. `jalr x0, 0(x1)`과 같이 사용하면 `x1`에 저장된 복귀 주소로 되돌아가는 기능을 수행하며, `x0`에 결과 주소를 저장하지 않음으로써 단순한 리턴 동작을 완성합니다.
